# HDLC（高级数据链路控制协议）

## 📖 定义-解释-示例

### 什么是 HDLC？

**HDLC**（High-Level Data Link Control）是 ISO 制定的**面向比特的数据链路层协议**，是所有数据链路层协议的"鼻祖"。HDLC 出生得早（1979 年由 IBM 的 SDLC 发展而来），但它定义了数据链路层最核心的概念：**成帧（Framing）、流量控制、差错检测**，这些概念直接影响了后来的 PPP、以太网等协议。

HDLC 是**面向连接**的协议，通信前需要建立逻辑连接，结束后释放连接。它天然支持**点到点**和**多点**两种拓扑结构，既可用于专线连接，也可用于共享介质。

### HDLC 的帧结构

HDLC 帧包含 6 个字段。每一个字段都有精确的功能定义：

```
┌──────┬─────┬─────┬──────┬─────┬──────┐
│ Flag │Addr │Ctrl │ Data │ FCS │ Flag │
│01111110│8bit│8/16bit│N×8bit│16/32bit│01111110│
└──────┴─────┴─────┴──────┴─────┴──────┘
```

1. **标志字段（Flag）**：固定值 `01111110`（0x7E），既是帧定界符，也是帧间填充。两个 Flag 之间的内容就是一帧。在同一帧的首尾各一个 Flag。正因为 Flag 的特殊角色，帧内数据不能出现 `01111110` 这个模式——这引出了 **比特填充** 技术。

2. **地址字段（Addr）**：在多点链路中标识次站地址。点到点链路中可以省略或用 `11111111` 表示广播。

3. **控制字段（Ctrl）**：HDLC 的灵魂字段，区分帧类型：
   - **I 帧（信息帧）**：控制字段第 1 位为 0，携带用户数据
   - **S 帧（监督帧）**：控制字段第 1-2 位为 10，用于流量控制和差错控制（RR/RNR/REJ/SREJ）
   - **U 帧（无编号帧）**：控制字段第 1-2 位为 11，用于链路建立、拆除、参数协商

4. **数据字段（Data）**：上层交付的数据，长度可变但必须是 8 比特的整数倍。

5. **帧校验序列（FCS）**：CRC 校验码，默认 16 位（CRC-16），可选 32 位（CRC-32）。对地址、控制、数据三个字段进行校验。

### 比特填充技术

**比特填充（Bit Stuffing）** 是 HDLC 最精妙的设计之一。由于 Flag 是 `01111110`，如果数据中出现了 6 个连续的 1，接收方会误以为到了帧尾。解决方案：发送方在数据中每遇到 5 个连续的 1 就自动在后面插入一个 0。接收方在去帧时，每看到 5 个连续的 1 就检查第 6 位：如果是 0，删掉它（填充位）；如果是 1，检查第 7 位确定是 Flag 还是错误。

**示例**：
- 原始数据：`...01111110...`（恰好等于 Flag！）
- 比特填充后：`...011111010...`（在第 5 个 1 后插入 0）
- 接收方恢复：删掉 5 个连续 1 后面的那个 0

这样保证了 Flag 的**唯一性**——Flag 模式永远不会在帧内出现。

### HDLC 的三种操作模式

**1. 正常响应模式（NRM）**
主站控制一切，次站必须获得主站许可才能发送数据。这是典型的**主从结构**，适合终端-主机的集中式网络。SDLC 和早期 IBM 网络主要使用此模式。

**2. 异步平衡模式（ABM）**
双方地位平等，都是组合站（可同时充当主站和次站），无需等待许可即可随时发送数据。这是**点对点**通信的默认模式，现代应用几乎全部使用 ABM。PPP 协议就派生自 HDLC 的 ABM 模式。

**3. 异步响应模式（ARM）**
次站可在未获主站许可时主动发送，但主站仍负责链路管理。适用范围较窄。

### HDLC 的流量控制与差错控制

**流量控制——滑动窗口协议**：
- I 帧携带发送序号 N(S) 和接收序号 N(R)
- N(R) 是对已正确接收帧的确认，同时允许发送方再发送 W（窗口大小）个帧
- 收到了 N(R)=5 意味着：0~4 号帧已确认，请发送 5 号帧

**差错控制——Go-Back-N 与选择重传**：
- **REJ（拒绝）**：等同于 Go-Back-N，从指定序号起重传所有帧
- **SREJ（选择拒绝）**：等同于选择重传，只重传指定的那一帧
- **超时重传**：规定时间内未收到确认，自动重传

### HDLC 的历史地位与现代影响

HDLC 是数据链路层协议的"万物之源"。它的 DNA 散落在几乎所有后续协议中：

- **PPP** 的帧格式直接复制了 HDLC 的 Flag → Addr → Ctrl → Data → FCS → Flag 结构
- **以太网**虽然帧格式不同，但 CRC 校验、成帧概念来自 HDLC
- **LAPB/LAPD/LAPF**（X.25、ISDN、帧中继的数据链路层）都是 HDLC 家族的直系后代
- **PPP 的 HDLC-like 帧** 是广域网链路最常用的封装格式

在现代网络中，纯粹的 HDLC 已不常见了（只在特定 Cisco 设备上作为串口的默认封装格式），但它奠定的**成帧、校验、流控**三大框架，至今仍是所有数据链路层协议的基础。
