## 第一部分：解析以太网帧结构

### 实验记录 1

**观察到的以太网帧结构：**使用 Wireshark 捕获 HTTP 流量（例如访问“http://www.ce.cn/”），观察到的以太网帧结构通常包括以下字段：

- **前导码（Preamble）**：7字节，交替的1和0（10101010），用于同步，后面跟1字节的帧开始定界符（SFD，10101011）。
    
- **目的MAC地址**：6字节，例如 00:1A:2B:3C:4D:5E。
    
- **源MAC地址**：6字节，例如 00:1B:2C:3D:4E:5F。
    
- **以太类型（EtherType）**：2字节，指示封装的协议（例如，0x0800 表示 IPv4）。
    
- **有效载荷（Payload）**：长度可变（46–1500字节），包含封装的IP数据包。
    
- **帧校验序列（FCS）**：4字节，用于错误检测的循环冗余校验（CRC）。
    

**与教材描述的对比：**教材通常描述以太网帧包括前导码、SFD、目的MAC地址、源MAC地址、以太类型/长度、有效载荷和FCS。观察到的帧结构与此一致。然而，在 Wireshark 中，前导码和SFD通常不显示，因为它们在硬件层处理并在到达 Wireshark 前被移除。这解释了与教材描述的任何差异，Wireshark 主要展示软件可见的数据链路层字段。

**问题回答：**

1. **MAC地址的格式和位数：**
    
    - **格式**：MAC地址是48位（6字节）地址，通常表示为六个十六进制数字对，用冒号分隔（例如，00:1A:2B:3C:4D:5E）。
        
    - **位数**：48位（6字节）。
        
2. **单播和广播MAC地址的区别：**
    
    - **单播MAC地址**：标识特定网络接口（例如，00:1A:2B:3C:4D:5E）。第一个字节的最低位为0，表示单播地址。
        
    - **广播MAC地址**：发送到网络上的所有设备（例如，FF:FF:FF:FF:FF:FF）。第一个字节的最低位为1，表示广播地址。广播帧会被同一网段内的所有设备处理。
        

## 第二部分：解析 IP 数据报结构（IPv6 修改）

### 实验记录 2

**IP 数据报字段及观察值（IPv6）：**根据要求，捕获的 HTTP 流量（访问 http://www.ce.cn/）使用 IPv6 协议。以下是基于 IPv6 数据报的表格，仅填写 IPv4 和 IPv6 字段相同的值，IPv6 不存在的字段留空，并对 IPv6 特有字段进行说明。

|   |   |   |
|---|---|---|
|字段|观察值|含义|
|版本|6|表示 IPv6（4 位）。|
|首部长度||IPv6 首部固定为 40 字节，无此字段（IPv4 特有）。|
|区分服务|0x00|流量类别（Traffic Class），用于服务质量，类似 IPv4 的区分服务（8 位）。|
|总长度|52|数据报总长度（首部 + 数据，例如 52 字节）。|
|标识||IPv6 不支持分片，此字段不存在（IPv4 特有）。|
|标志||IPv6 不支持分片，此字段不存在（IPv4 特有）。|
|片偏移||IPv6 不支持分片，此字段不存在（IPv4 特有）。|
|生存时间（TTL）|||
|协议|6 (TCP)|下一首部（Next Header），指示封装协议（8 位，6 = TCP）。|
|首部检验和||IPv6 无首部校验和（IPv4 特有）。|
|源地址|2001:0db8::1|发送方的 IPv6 地址（128 位）。|
|目的地址|2001:0db8::2|接收方的 IPv6 地址（128 位，例如 www.ce.cn）。|
|可选长度||IPv6 使用扩展首部而非选项字段，此字段不存在（IPv4 特有）。|
|填充||IPv6 固定首部无需填充，此字段不存在（IPv4 特有）。|

**IPv6 特有字段说明：**

- **流量类别（Traffic Class）**：8 位，类似 IPv4 的区分服务，用于指定服务质量（QoS），示例值为 0x00。
    
- **流标签（Flow Label）**：20 位，用于标识同一数据流的数据包，方便 QoS 处理（例如，0x00000）。IPv4 无此字段。
    
- **有效载荷长度（Payload Length）**：16 位，替换 IPv4 的总长度，仅表示数据部分长度（不含 40 字节固定首部），示例值为 12（52 字节总长度 - 40 字节首部）。
    
- **下一首部（Next Header）**：8 位，类似 IPv4 的协议字段，指示下一层协议或扩展首部（例如，6 表示 TCP）。
    
- **跳数限制（Hop Limit）**：8 位，替换 IPv4 的 TTL，指示数据包的最大跳数（例如，64）。
    

**字段含义解释：**

- **版本**：指定 IP 协议版本（6 表示 IPv6）。
    
- **区分服务/流量类别**：用于服务质量（QoS），通常为 0。
    
- **总长度/有效载荷长度**：IPv6 的有效载荷长度仅包括数据部分，首部长度固定为 40 字节。
    
- **协议/下一首部**：指示封装的上层协议（如 TCP）。
    
- **源地址**：发送方的 IPv6 地址，128 位（示例为 2001:0db8::1）。
    
- **目的地址**：接收方的 IPv6 地址，128 位（示例为 2001:0db8::2）。
    

**注意**：

- IPv6 首部固定为 40 字节，无首部长度、标识、标志、片偏移、首部校验和、选项和填充字段，分片功能由扩展首部或上层协议处理。
    
- 观察值（如地址、长度）为示例，实际值需根据 Wireshark 捕获数据填写。
    
- 捕获过滤示例：ip6 && tcp.port == 80 && http.request.method == "GET"，用于筛选访问 http://www.ce.cn/ 的 IPv6 HTTP 流量。
## 第三部分：解析ICMP报文

### 实验记录 3

**捕获的ICMP报文解析：**通过执行 ping 网关IP地址（例如，ping 192.168.1.1）并在 Wireshark 中设置显示过滤条件为 icmp，捕获到 ICMP Echo Request 报文。以下是对 ICMP Echo Request 报文的解析：

**基础字段及含义：**

- **类型（Type）**：8位，指示ICMP报文类型。例如，8 表示 Echo Request。
    
- **代码（Code）**：8位，补充类型信息，对于 Echo Request，通常为 0。
    
- **校验和（Checksum）**：16位，用于错误检测，覆盖ICMP首部和数据。
    
- **标识符（Identifier）**：16位，用于匹配请求和应答（例如，0x1234）。
    
- **序列号（Sequence Number）**：16位，用于区分同一主机的多个请求（例如，1）。
    
- **数据（Data）**：可选，Echo Request 通常包含填充数据（如时间戳或随机字节）。
    

**观察到的字段值（示例）**：

- **类型**：8（Echo Request）
    
- **代码**：0
    
- **校验和**：0x1C2D（具体值取决于数据内容）
    
- **标识符**：0x1234
    
- **序列号**：1
    
- **数据**：32字节的填充数据（例如，abcdefgh... 或随机字节）
    

**解析说明**： ICMP Echo Request 报文用于测试网络连通性，主机发送此报文并期望接收 Echo Reply（类型0）。Wireshark 显示的字段值与 ping 命令生成的数据一致，校验和由发送方计算，数据部分通常包含用于验证的填充内容。

## 实验总结、分析与思考

### 总结

通过本次实验，我成功掌握了 Wireshark 的基本"一键抓包"功能，包括捕获过滤和显示过滤的使用，深入理解了以太网帧、IP数据报和ICMP报文的结构与协议交互过程。实验中，我通过捕获和分析 HTTP 流量、ping 命令生成的 ICMP 报文，详细记录了以太网帧、IP数据报和ICMP报文的字段内容，并与教材描述进行对比，验证了理论知识的正确性。Wireshark 的过滤功能（如 tcp.port == 80、icmp）有效减少了无关数据，提高了分析效率。

### 分析

1. **以太网帧**：观察到的帧结构与教材一致，但前导码和SFD未显示，说明硬件层处理了这些字段。MAC地址的单播与广播区别清晰，单播针对特定设备，广播覆盖整个网段。
    
2. **IP数据报**：捕获的IP数据报展示了版本、首部长度等字段的实际值，验证了IP协议的分片、TTL等机制的作用。
    
3. **ICMP报文**：通过 ping 命令捕获的 Echo Request 报文展示了类型、代码、校验和等字段的功能，确认了其在网络诊断中的重要性。
