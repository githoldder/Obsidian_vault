实验三  分布式多模块通信

**一、  实验目的**

掌握多模块项目的基本通信，实现跨服务调用。

**二、  实验环境**

1．本实验采用的是IDEA2021.3开发环境；

2．创建workspace文件夹，在该文件夹下创建springboot-parent的springboot项目；

3．在springboot-parent下创建user和order子模块

4.本次实验说明：单人完成，实验地点为个人电脑，时间2026年5月19日。

**三、  实验内容与要求**

1． 本实验要求在 windows 下使用；

2． 新建workspace文件夹；

在workspace文件夹下创建springboot-parent的springboot项目；

3． 将user和order注入consul中

4． 在user模块中配置openfeign调用order模块中的服务

5． 测试并验证结果正确性。

**四、  实验预习和准备**

参考相关书籍，能够熟练地安装和使用IDEA2021.3相关开发工具。

**五、  实验过程与结果**

### 步骤1：用Docker启动Consul服务注册中心

打开终端，执行以下命令拉取并启动Consul容器（开发模式）：

```bash
docker run -d --name consul -p 8500:8500 -p 8600:8600/udp hashicorp/consul:latest agent -dev -client=0.0.0.0
```

验证Consul是否启动成功：

```bash
curl http://localhost:8500/v1/status/leader
```

若返回 `"127.0.0.1:8300"` 则表示Consul已正常运行。

### 步骤2：在IDEA中创建springboot-parent父工程

1. 打开IDEA → File → New → Project
2. 选择 Spring Initializr，填写以下信息：
   - Group: `com.example`
   - Artifact: `springboot-parent`
   - Type: Maven
   - Language: Java
   - Spring Boot: 3.2.5
3. 保存位置选择 workspace 文件夹下
4. 创建完成后，修改 `pom.xml`，将 `<packaging>jar</packaging>` 改为 `<packaging>pom</packaging>`，删除 `<build>` 中的 `spring-boot-maven-plugin` 插件（父工程不需要打包）

最终父工程 `pom.xml` 内容如下：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.5</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>springboot-parent</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>pom</packaging>
    <name>springboot-parent</name>
    <description>Distributed multi-module communication project</description>

    <modules>
        <module>user-service</module>
        <module>order-service</module>
    </modules>

    <properties>
        <java.version>17</java.version>
        <spring-cloud.version>2023.0.1</spring-cloud.version>
    </properties>

    <dependencyManagement>
        <dependencies>
            <dependency>
                <groupId>org.springframework.cloud</groupId>
                <artifactId>spring-cloud-dependencies</artifactId>
                <version>${spring-cloud.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
        </dependencies>
    </dependencyManagement>

</project>
```

**关键说明**：
- `<packaging>pom</packaging>` 表示这是聚合父工程，不生成jar包
- `<modules>` 声明两个子模块
- `<dependencyManagement>` 统一管理 Spring Cloud 版本，避免子模块版本冲突
- 删除了 src 目录和 spring-boot-maven-plugin（父工程只是容器，不运行）

#### 3.2 order-service 的 application.yml

删除默认的 application.properties，新建 `application.yml`：

```yaml
server:
  port: 8081

spring:
  application:
    name: order-service
  cloud:

      port: 8500
      discovery:
        service-name: order-service

        health-check-interval: 10s

management:
  endpoints:
    web:
```

**配置说明**：

- `health-check-path`：健康检查路径，Consul每10秒访问一次
- `register: true`：启动时自动注册到Consul
- `management.endpoints.web.exposure.include`：暴露health和info端点

#### 3.4 OrderController.java 订单控制器

```java
package com.example.order.controller;

import org.springframework.web.bind.annotation.*;

import java.util.*;

@RestController
@RequestMapping("/order")
public class OrderController {

    // 模拟订单数据
    private static final Map<Long, String> ORDER_DB = new HashMap<>();

    static {
        ORDER_DB.put(1L, "iPhone 16 Pro");
        ORDER_DB.put(2L, "MacBook Air M4");
        ORDER_DB.put(3L, "AirPods Pro 3");
    }

    @GetMapping("/{id}")
    public Map<String, Object> getOrder(@PathVariable Long id) {
        Map<String, Object> result = new HashMap<>();
        String product = ORDER_DB.get(id);
        if (product != null) {
            result.put("code", 200);
            result.put("orderId", id);
            result.put("product", product);
            result.put("message", "订单查询成功");
        } else {
            result.put("code", 404);
            result.put("message", "订单不存在");
        }
        return result;
    }

    @GetMapping("/list")
    public Map<String, Object> listOrders() {
        Map<String, Object> result = new HashMap<>();
        result.put("code", 200);
        result.put("orders", ORDER_DB);
        result.put("message", "订单列表查询成功");
        return result;
    }
}
```

提供了两个接口：
- `GET /order/{id}`：根据ID查询单个订单
- `GET /order/list`：查询全部订单列表

#### 4.3 UserApplication.java 启动类

```java
package com.example.user;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.openfeign.EnableFeignClients;

@SpringBootApplication
@EnableFeignClients  // 启用Feign客户端扫描
public class UserApplication {
    public static void main(String[] args) {
        SpringApplication.run(UserApplication.class, args);
    }
}
```

**关键点**：`@EnableFeignClients` 注解是必须的，它会扫描带有 `@FeignClient` 注解的接口并生成代理实现类。缺少此注解会导致注入 OrderClient 时报错。

> 📸 截图占位：UserApplication.java

#### 4.4 OrderClient.java（OpenFeign声明式客户端）

```java
package com.example.user.client;

import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.*;

import java.util.Map;

@FeignClient(name = "order-service")
public interface OrderClient {

    @GetMapping("/order/{id}")
    Map<String, Object> getOrder(@PathVariable("id") Long id);

    @GetMapping("/order/list")
    Map<String, Object> listOrders();
}
```

**核心原理**：
- `@FeignClient(name = "order-service")`：name属性的值 `order-service` 对应order-service在Consul中注册的服务名
- Feign会通过Consul服务发现获取order-service的实际IP和端口，无需硬编码地址
- 这是一个纯接口，Feign在运行时自动生成代理实现，发送HTTP请求到order-service

**易错点**：`@PathVariable("id")` 必须显式指定value值，因为Feign是通过接口生成的代理，参数名在编译后可能丢失。

#### 4.5 UserController.java（调用方控制器）

```java
package com.example.user.controller;

import com.example.user.client.OrderClient;
import org.springframework.web.bind.annotation.*;

import java.util.*;

@RestController
@RequestMapping("/user")
public class UserController {

    private final OrderClient orderClient;

    public UserController(OrderClient orderClient) {
        this.orderClient = orderClient;
    }

    @GetMapping("/order/{id}")
    public Map<String, Object> getUserOrder(@PathVariable Long id) {
        Map<String, Object> result = new HashMap<>();
        result.put("userId", 1001L);
        result.put("username", "张三");

        // 通过 OpenFeign 调用 order-service
        Map<String, Object> orderInfo = orderClient.getOrder(id);
        result.put("orderInfo", orderInfo);
        result.put("message", "用户订单查询成功（跨服务调用）");
        return result;
    }

    @GetMapping("/orders")
    public Map<String, Object> getUserOrders() {
        Map<String, Object> result = new HashMap<>();
        result.put("userId", 1001L);
        result.put("username", "张三");

        // 通过 OpenFeign 调用 order-service
        Map<String, Object> orderList = orderClient.listOrders();
        result.put("orderList", orderList);
        result.put("message", "用户订单列表查询成功（跨服务调用）");
        return result;
    }
}
```

**调用链路**：UserController → OrderClient（Feign代理）→ Consul服务发现 → order-service

### 步骤9：实验中遇到的问题及解决

**问题1：Spring Cloud 2023.x 版本 OpenFeign 启动报错**

报错信息：`No Feign Client for loadBalancing defined. Did you forget to include spring-cloud-starter-loadbalancer?`

原因：Spring Cloud 2023.x 移除了Ribbon，OpenFeign需要显式引入 LoadBalancer 依赖。

解决：在 user-service 的 pom.xml 中添加：

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>
```

**问题2：@PathVariable 在Feign接口中参数名丢失**

如果在 OrderClient 接口中只写 `@PathVariable Long id` 而不指定 value，Feign代理生成的请求路径可能不包含正确的参数值。

解决：显式指定value：`@PathVariable("id") Long id`

**六、  实验小结和体会**

通过本次实验，我掌握了以下内容：

1. **多模块项目构建**：使用Maven的pom聚合方式创建父工程管理子模块，通过dependencyManagement统一管理Spring Cloud依赖版本，避免了子模块间版本冲突。父工程的packaging必须设为pom，且不需要src目录和spring-boot-maven-plugin。

2. **Consul服务注册与发现**：通过Docker快速部署Consul开发模式，Spring Boot应用只需引入spring-cloud-starter-consul-discovery依赖并配置连接信息，即可自动将服务注册到Consul。Actuator的health端点作为健康检查，Consul每10秒检测一次服务存活状态。

3. **OpenFeign跨服务调用**：OpenFeign是声明式HTTP客户端，只需定义接口并标注@FeignClient(name = "order-service")，无需手动编写HTTP调用代码。Feign结合Consul服务发现和LoadBalancer，自动从Consul获取目标服务的实例地址并进行负载均衡调用。整个调用过程对业务代码完全透明。

4. **服务调用链路**：user-service (8082) → Consul服务发现 → order-service (8081)，完整体验了微服务架构中"服务注册 → 服务发现 → 远程调用"的核心模式。

5. **版本兼容性**：Spring Cloud 2023.x版本中OpenFeign不再内置Ribbon，必须显式引入spring-cloud-starter-loadbalancer作为负载均衡实现，这是与旧版本的重要区别。
