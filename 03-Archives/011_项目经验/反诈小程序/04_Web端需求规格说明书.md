## 2. 系统概述

### 2.1 系统定位

Web端是仙龙社区租赁住房管理平台的**管理后台**，面向三类用户角色：

| 角色 | 权限范围 | 核心功能 |
|------|----------|----------|
| **超级管理员（民警）** | 全局数据访问 | 预警裁决、账号分发、全局可视化 |
| **管理员（网格员）** | 区域权限 | 数据审查、增删改查、导出报表 |
| **普通用户（二房东）** | 自有房源 | 信息上报、查看记录 |

### 2.2 Web端核心目标

> **Web端给领导看，强调视觉效果UI/UX设计科技感**

- 数据可视化展示
- 决策辅助
- 信息概览

## 3. 功能模块需求

### 3.1 二房东模块

#### 3.1.1 功能描述

展示二房东个人信息及其房源信息。

#### 3.1.2 界面要素

| 要素 | 说明 |
|------|------|
| **个人信息列表** | 以列表形式展示所有二房东基本信息 |
| **详情查看** | 点击可查看具体的个人信息和手中房源信息 |

#### 3.1.3 数据字段

- 二房东姓名
- 身份证号（脱敏显示）
- 联系电话
- 持有房源数量
- 房源状态统计

---

### 3.2 房源模块

#### 3.2.1 颜色逻辑（核心视觉标识）

| 状态 | 颜色 | 说明 |
|------|------|------|
| **主题色** | 蓝色 | 平台主色调 |
| **正常状态** | 绿色 | 房源正常、无异常 |
| **房源不安全** | 红色 | 房源存在安全隐患 |
| **人员不安全** | 黄色 | 居住人员存在风险 |

> 异常登记状态更新后自动标记对应颜色

#### 3.2.2 特殊标记功能

| 功能 | 说明 |
|------|------|
| **特殊处理文本框** | 登记记录房源特殊处理（经常报警、犯罪等特殊情况） |
| **标签管理** | 犯罪/违法行为标签（管理员自定义） |
| **标签分级** | 三级分级管理 |

**标签颜色分级：**

| 级别 | 颜色 | 说明 |
|------|------|------|
| 一般 | 淡黄色 | 轻微关注 |
| 关注 | 橙黄色 | 中度关注 |
| 管控 | 深红色 | 高度管控 |

#### 3.2.3 房源交互效果

**点击楼栋 → 弹出单元信息：**

- 甲单元、乙单元（正常情况两个模块按钮）
- 预留丙单元（扩展用）

**弹出信息包含：**
- 单元名称
- 租赁房户数
- 其他统计信息

#### 3.2.4 房源分类统计

| 分类 | 说明 |
|------|------|
| **整租房** | 独立出租的完整房源 |
| **合租房** | 多户共享的房源 |
| **空置房** | 当前无人居住的房源数量统计 |
| **自住房** | 房东自住的房源数量统计 |

> 二房东信息不单独分类展示

---

### 3.3 流动人口模块

#### 3.3.1 功能列表

| 功能 | 说明 |
|------|------|
| **新增** | 录入新的流动人口信息 |
| **注销** | 人员离开/退房处理 |
| **现有** | 查看当前在住人员列表 |

#### 3.3.2 一键注销功能

**业务逻辑：**

1. 用户点击「注销」
2. 房源信息状态恢复
3. 房源颜色恢复正常
4. 实体数据逻辑绑定（人员与房源状态联动）

---

### 3.4 地图可视化模块

#### 3.4.1 功能描述

基于百度地图API，实现房源的地理位置可视化展示。

#### 3.4.2 展示层级

| 层级      | 说明          |
| ------- | ----------- |
| **社区级** | 以社区为最小展示单位  |
| **楼栋级** | 点击楼栋展示户型结构图 |
| **房间级** | 详细到房间的住户信息  |

#### 3.4.3 地图功能

- 房源定位标记（颜色区分状态）
- 点击查看详情
- 区域统计概览

## 4. 非功能需求

### 4.1 UI/UX 设计要求

#### 4.1.1 视觉风格

- **科技感**：现代、简洁、专业的界面设计
- **数据驱动**：图表化展示关键指标
- **响应式**：适配不同屏幕尺寸

#### 4.1.2 交互原则

- **一键操作**：核心功能一键完成（如一键注销）
- **层级导航**：清晰的面包屑导航
- **状态反馈**：操作结果即时反馈

### 4.2 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载时间 | ≤ 3秒 |
| 数据刷新延迟 | ≤ 2秒 |
| 大数据量渲染 | 支持数万条数据流畅展示 |

### 4.3 安全要求

| 要求 | 说明 |
|------|------|
| 数据加密 | 敏感信息（身份证、电话）脱敏展示 |
| 权限隔离 | 三级权限管理，数据可见性控制 |
| 操作日志 | 关键操作留痕审计 |

## 5. 数据需求

### 5.1 核心数据实体

```
房源实体（核心）
├── 向上关联：二房东（普通用户）
├── 向下关联：租客（人员信息）
└── 空间关联：经纬度坐标（1:1）
```

### 5.2 数据隔离

| 角色 | 数据范围 |
|------|----------|
| 超级管理员 | 全局数据 |
| 管理员 | 所属网格区域 |
| 普通用户 | 绑定的房源ID |

### 5.3 数据状态机

```
二房东上报 → 网格员初审 → 民警终审
     ↓              ↓           ↓
   待审核         审核中       已通过/驳回
```
