# 工厂模式（Factory Pattern）

## 📖 定义-解释-示例

### 什么是工厂模式？

**工厂模式**是创建型设计模式的统称，核心思想：**将对象的创建逻辑从使用逻辑中分离出来**，让客户端不需要知道具体类的名字或构造细节，只需通过一个"工厂"来获取对象。

工厂模式家族包含三个变体：
1. **简单工厂（Simple Factory）**：一个静态方法，根据参数返回不同类型。不是 GoF 23 种设计模式之一，但最常见
2. **工厂方法（Factory Method）**：定义一个创建对象的接口，让子类决定实例化哪个类。GoF 的正式模式
3. **抽象工厂（Abstract Factory）**：创建一系列相关或依赖对象的接口，无需指定具体类

它们的递进关系：简单工厂 → 一个工厂多个产品；工厂方法 → 一个产品等级多个子类工厂；抽象工厂 → 多个产品等级多个子类工厂。

### 简单工厂——最实用的入门

```java
// 没有工厂——客户端需要知道所有具体类
Pizza orderPizza(String type) {
    Pizza pizza;
    if (type.equals("cheese")) {
        pizza = new CheesePizza();
    } else if (type.equals("pepperoni")) {
        pizza = new PepperoniPizza();
    } else if (type.equals("veggie")) {
        pizza = new VeggiePizza();
    }
    pizza.prepare();
    pizza.bake();
    pizza.cut();
    pizza.box();
    return pizza;
}
```

问题：每次加新披萨类型 → 要修改这段代码。这段"if-else 类型选择"逻辑到处都是。

**引入简单工厂**：

```java
class SimplePizzaFactory {
    public Pizza createPizza(String type) {
        return switch (type) {
            case "cheese" -> new CheesePizza();
            case "pepperoni" -> new PepperoniPizza();
            case "veggie" -> new VeggiePizza();
            default -> throw new IllegalArgumentException("Unknown pizza: " + type);
        };
    }
}

class PizzaStore {
    private SimplePizzaFactory factory;
    
    public PizzaStore(SimplePizzaFactory factory) {
        this.factory = factory;
    }
    
    public Pizza orderPizza(String type) {
        Pizza pizza = factory.createPizza(type);
        pizza.prepare();
        pizza.bake();
        pizza.cut();
        pizza.box();
        return pizza;
    }
}
```

现在所有创建逻辑集中在一个地方。需要加新类型？改工厂即可。如果创建逻辑变了（比如需要不同的构造函数参数），只需修改一处。**简单工厂的本质 = 对象创建的封装**。

### 工厂方法——让子类决定

简单工厂的问题是违反开闭原则——增加新产品需要修改工厂类。**工厂方法**通过继承解决：

```java
// 抽象创建者——定义框架，延迟创建给子类
abstract class PizzaStore {
    public Pizza orderPizza(String type) {
        Pizza pizza = createPizza(type);  // 工厂方法！
        pizza.prepare();
        pizza.bake();
        pizza.cut();
        pizza.box();
        return pizza;
    }
    
    protected abstract Pizza createPizza(String type);  // 子类实现
}

// 纽约风味的工厂
class NYPizzaStore extends PizzaStore {
    protected Pizza createPizza(String type) {
        return switch (type) {
            case "cheese" -> new NYCheesePizza();
            case "pepperoni" -> new NYPepperoniPizza();
            default -> throw new IllegalArgumentException("Unknown: " + type);
        };
    }
}

// 芝加哥风味的工厂
class ChicagoPizzaStore extends PizzaStore {
    protected Pizza createPizza(String type) {
        return switch (type) {
            case "cheese" -> new ChicagoCheesePizza();
            case "pepperoni" -> new ChicagoPepperoniPizza();
            default -> throw new IllegalArgumentException("Unknown: " + type);
        };
    }
}
```

**关键设计**：`orderPizza()` 是**模板方法**——定义了制作披萨的固定步骤，但把"创建哪种披萨"推迟到子类实现。父类不需要知道具体是什么披萨，只知道有一个 `createPizza()` 抽象方法会返回一个 `Pizza`。

**工厂方法的价值**：要增加新的披萨风格（如加州风味）？新建 `CaliforniaPizzaStore` 子类，实现 `createPizza()`——不改已有代码。开闭原则完美满足。

### 抽象工厂——创建产品族

当需要创建一系列相关对象时，抽象工厂上场：

```java
// 抽象工厂——定义创建一系列相关产品的接口
interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

// 具体工厂——Windows 风格
class WindowsFactory implements GUIFactory {
    public Button createButton() { return new WindowsButton(); }
    public Checkbox createCheckbox() { return new WindowsCheckbox(); }
}

// 具体工厂——macOS 风格
class MacFactory implements GUIFactory {
    public Button createButton() { return new MacButton(); }
    public Checkbox createCheckbox() { return new MacCheckbox(); }
}
```

客户端代码：

```java
class Application {
    private GUIFactory factory;
    
    public Application(GUIFactory factory) {
        this.factory = factory;  // 运行时决定风格
    }
    
    public void render() {
        Button btn = factory.createButton();
        Checkbox cb = factory.createCheckbox();
        // btn 和 cb 风格一致：要么全 Windows，要么全 Mac
    }
}
```

**抽象工厂的契约保证**：`WindowsFactory` 创建的 `Button` 和 `Checkbox` 在视觉风格上天然一致。你不会收到一个 Windows 按钮配一个 Mac 复选框。产品族的一致性由工厂保证。

### 三者的选择指南

| 需求 | 推荐模式 | 原因 |
|------|----------|------|
| 简单对象创建，类型不常变 | 简单工厂 | 够用，实现成本最低 |
| 创建不同类型，但框架固定 | 工厂方法 | 符合OCP，新增子类型不用改代码 |
| 需要保证产品族一致性 | 抽象工厂 | 天然保证"系列"的一致性 |
| 极度复杂的对象构造（很多参数） | Builder 模式 | 工厂模式不适合多参数构造 |

### 工厂模式的现代替代——依赖注入

在现代 Java/Spring 生态中，手工写工厂类越来越少见——**依赖注入容器**（Spring IoC 容器）替代了传统工厂的大部分功能：

```java
@Service
class PizzaService {
    @Autowired  // Spring 自动注入——相当于内置的"工厂"
    private PizzaFactory pizzaFactory;
}
```

但理解工厂模式依然重要：
- 框架的 IoC 容器本质上就是**巨大的抽象工厂**
- 不是所有项目都使用 Spring
- 理解工厂 = 理解"为什么 DI 容器这样设计"
