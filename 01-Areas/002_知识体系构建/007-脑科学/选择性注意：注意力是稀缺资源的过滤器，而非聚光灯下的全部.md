## 一、底层原理（为什么它成立）

1. **通道带宽有限**：感觉器官每秒接收约 10⁷ bit 信息，但意识加工能力仅约 10² bit（Nørretranders 估算）。海量输入、狭小出口，**过滤是生理必然而非性格缺陷**。

2. **双耳分听证据**：被试能一字不差复述"注意耳"内容，但对另一只耳的内容几乎零记忆——甚至没察觉换语种、换说话人。

3. **过滤器并非全关**：Moray（1959）发现约 1/3 的被试在"未注意耳"中听到了自己的名字。说明未注意通道仍在被持续、低强度地加工——**注意之外不是虚无，而是被调小音量的暗流**。

4. **激活阈值机制**：与自我高度相关的信号（名字、危险词如"着火"）因熟悉度高、激活阈值低，能"穿透"衰减闯入意识。这就是你能在喧嚣中一秒抓住自己名字的原因。

## 二、模型框架（它长什么样）

把注意力想象成一个**四级过滤漏斗 + 低阈值旁路**：

| 层级      | 机制                   | 类比     |
| ------- | -------------------- | ------ |
| ① 感觉缓冲器 | 感觉记忆短暂暂存原始输入         | 入口排队区  |
| ② 主过滤器  | 按物理特征（方位、音色、音量）衰减/放行 | 门禁闸机   |
| ③ 语义旁路  | 低阈值词（名字/危险词）无视闸机直接闯入 | VIP 通道 |
| ④ 工作记忆  | 被放行的信息进入意识精细加工       | 会议室    |

- **早期选择派**（Broadbent）：闸机在最前面，按物理特征过滤。

- **衰减派**（Treisman）：闸机不阻断只降音量，重要词阈值低仍能通过。

- **后期选择派**（Deutsch/Norman）：所有信息先识别语义，再由第二道闸机按重要性筛入工作记忆。

- **容量派**（Kahneman）：注意是总量有限的资源，按唤醒水平和任务需求灵活分配——熟练司机在空旷高速上能边开车边聊天，在拥挤街道上就不能。

**核心命题**：你无法消灭漏斗，只能改造它的过滤规则和阈值清单。

## 三、操作步骤 / 方法（如何应用）

将"设计过滤规则"拆为四步（对应漏斗四层）：

1. **明确当前唯一通道（选闸机）**：每次只设一个"注意耳"——一个正在执行的任务。写下它，让主过滤器有明确的物理特征可匹配（如：只开一个窗口、只放一份文档在桌面）。

2. **把低阈值词单改写进环境（设 VIP 通道）**：大脑会自动响应"名字级"信号。主动利用它——把重要截止日期、关键人名设成手机最高优先级提醒；反之，把高频干扰词（群消息、推送）从视野中物理移除，避免它们冒充 VIP 反复闯入。

3. **管理容量而非意志（控总量）**：Kahneman 模型告诉你"分心"是容量超载而非道德问题。多任务并行前先问：这些任务的容量之和是否超过总量？超了就串行，或先自动化其中一个（如熟练开车）腾出余量。

4. **定期审计暗流（查衰减层）**：被调小音量的信息并没有消失。每周问一次："最近有什么我一直'知道存在'却始终没进入意识的事？"——它们往往正是阈值最低、最该升级处理的信号。

## 四、具体案例（抽象落地）

**案例 A：信息流降噪（个人）**

- 问题：每天刷 20 个群、5 个信息源，什么都没记住。

- 用模型拆解：② 层闸机失效（被动接收所有通道）+ ③ 层被劫持（推送词冒充低阈值词）。

- 操作：① 只保留 3 个"注意耳"信息源；② 关闭全部推送，改为每日 2 次主动拉取（把过滤从"自动衰减"改为"主动分诊"）；③ 设立"信号词单"——仅当消息含项目关键词时才升级阅读。

- 效果机制：不增加带宽，只改过滤规则。

**案例 B：会议与开发并行（工作）**

- 问题：边开会边写代码，两头都做砸。

- 用模型拆解：两项任务容量之和 > 总量（Kahneman），且代码任务的低阈值词（报错、群 @我）不断触发语义旁路劫持注意。

- 操作：串行化——开会时只开会；写代码前把手机物理隔离，把"@我"设成唯一会穿透的提醒（保留真正的 VIP 通道）。

**案例 C：学习中的"背景音"利用**

- 未注意通道仍在被低强度加工（衰减模型）——所以教材重读前先快速通读一遍做"预热"，让关键术语阈值降低；第二遍精读时这些词会更容易"穿透"进入意识，吸收效率更高。

## 五、边界与反例（何时失效）

- **不是万能聚光灯**：视觉搜索中"特征整合"需要注意逐个绑定特征，说明注意确实有空间指向性——聚光灯隐喻在视觉任务中部分成立，两种隐喻互补而非互斥。

- **阈值机制有副作用**：同一套低阈值词单也会导致确认偏误——你最担心的事总能"穿透"进来。审计暗流时警惕：频繁闯入的焦虑信号未必重要。

- **自动化有代价**：腾出容量靠的是练习自动化，而不是真"多任务"——所谓并行，只是把一个任务跑成后台进程，切换本身仍有成本（切换损耗，后续笔记关联）。
