# Project Delivery Pack

## 触发场景

- 需要完成一个完整项目并输出可展示、可交付、可挂 GitHub 的文档流。
- 需要写 PRD、MRD、BRD、用户故事、竞品分析或路线图。
- 需要写 SRS、概要设计、详细设计、数据库设计、接口文档、测试文档、部署文档或用户手册。
- 需要整理项目章程、WBS、进度计划、风险表、会议纪要和复盘报告。

## 输入

- 项目想法、需求访谈记录、已有原型或代码仓库。
- 目标读者：老师、面试官、甲方、团队成员或用户。
- 交付目标：课程作业、作品集、正式交付包或 GitHub 展示仓。

## 输出

- 三层文档包：产品层、软件工程层、项目管理层。
- 最小 MVP 文档包或完整交付文档包。
- GitHub README、docs 目录建议和交付检查清单。
- Sprint checkpoint 与复盘记录。

## 执行步骤

1. 判断项目阶段：想法、需求、原型、开发中、交付前、复盘。
2. 根据目标读者选择最小文档包或完整文档包。
3. 先建立文档目录与命名，再生成单个文档。
4. 产品层先明确问题、用户、价值和范围。
5. 工程层对齐需求、架构、数据、接口、测试和部署。
6. 管理层记录计划、风险、会议、变更和复盘。
7. 最后按质量检查清单审查并归档。

## 验收标准

- 文档之间编号、术语、功能范围一致。
- 每份正式文档有目标读者、版本、状态和变更记录。
- GitHub 作品集能让读者快速理解项目价值、技术实现和交付成果。
- 交付包能独立发给老师、甲方或面试官阅读。
