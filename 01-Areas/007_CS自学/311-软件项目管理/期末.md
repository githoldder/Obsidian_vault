# 软件项目管理：软件项目进度管理期末开卷知识体系

## 0. 去年试卷题型与答题手感

去年试卷结构：

| 题型 | 分值 | 形式 | 高分关键 |
|---|---:|---|---|
| 简答题 | 40分 | 4题，每题10分 | 定义 + 分点 + 作用/场景 |
| 案例分析 | 30分 | 1个案例，3小问，每问10分 | 每问通常写5点，每点2分 |
| 计算题 | 30分 | 2题 | 关键路径/赶工 + 决策树/期望值 |

去年简答题考法特点：

1. 题目并不难，但要求答案完整。只写名词不给解释容易丢分。
2. 答案倾向“4点或5点分点给分”，每点要有一句说明。
3. 对比题要写“相同点 + 不同点 + 各自优势”。
4. 案例题要把材料中的错误翻译成项目管理术语。
5. 计算题要写步骤，不能只给结果。

简答题通用模板：

```text
第一句：先下定义。
第二步：分点写核心内容，尽量写4-5点。
第三步：每点补一句作用、原因或例子。
最后一句：说明该过程要动态更新、贯穿项目全过程，或服务于按期交付。
```

案例题通用模板：

```text
指出问题类：没有做什么 + 做错什么 + 做得不完整。
应对措施类：事前分析 + 培训 + 测试 + 备份/切换 + 沟通/监控。
经验总结类：回归标准流程：规划、识别、分析、应对、监控。
```

## 1. 全章知识框架（PPT 2）

本章主线可以记成：

```text
进度管理规划
  -> 活动定义
  -> 活动排序
  -> 活动历时估算
  -> 制定进度计划
  -> 进度控制
```

可能简答问法：

- 软件项目进度管理主要包括哪些内容？
- 简述制定项目进度计划的一般过程。
- 为什么软件项目进度管理不能只等同于画甘特图？

标准答案：

软件项目进度管理是为了保证项目各项工作和项目总任务按时完成而进行的一系列管理活动。它一般包括进度管理规划、活动定义、活动排序、活动历时估算、制定进度计划和进度控制。前期通过计划和活动分解明确“要做什么、先后关系是什么、需要多久”，中期通过进度模型、甘特图、里程碑图等形成进度计划，后期通过偏差分析、趋势分析、关键路径法和挣值管理等手段监督进展并纠偏。

容易混淆：

- 进度管理不只是“排日期”，还包括计划规则、活动分解、依赖关系、历时估算、资源约束、压缩优化和控制纠偏。
- 甘特图只是进度计划的表现形式，不等于全部进度管理。

## 2. 进度管理规划（PPT 3-5）

### 2.1 时间的特点（PPT 4）

时间是一种特殊资源，具有：

1. 单向性：时间只能向前流逝，不能倒流。
2. 不可重复性：已经过去的时间无法重新使用。
3. 不可替代性：预算、人力、工具可以增加，但无法完全替代已经损失的时间。

常考选填：

```text
时间资源的三个特点：单向性、不可重复性、不可替代性。
```

简答扩展：

在软件项目中，时间的不可逆性使得进度延误具有累积效应。即使后期增加人员或加班，也可能因为沟通成本、学习成本、返工成本上升而无法完全追回前期延误。因此项目经理必须在早期进行合理估算、计划和监控。

### 2.2 项目时间管理/项目进度管理（PPT 4）

定义：

项目时间管理又称项目进度管理，是指为保证项目各项工作及项目总任务按时完成所需要的一系列工作与过程。

作用：

1. 明确项目活动的先后顺序和持续时间。
2. 协调项目范围、资源、成本和质量之间的关系。
3. 为项目执行提供时间安排依据。
4. 为进度控制提供基准。
5. 帮助项目经理发现延误风险并及时纠偏。

可能简答问法：

- 什么是项目进度管理？
- 项目进度管理为什么重要？

高分答案：

项目进度管理是为了保证项目各项工作及项目总任务按时完成而进行的一系列工作和过程。它不仅包括制定进度计划，还包括活动定义、活动排序、活动历时估算、资源和进度约束分析、进度基准建立以及进度控制。其作用是保证项目按期交付，协调资源使用，发现和处理进度偏差，并为项目绩效评价提供依据。

### 2.3 项目活动（PPT 4）

定义：

项目活动是为完成工程项目而必须进行的具体工作，包括管理工作。

地位：

项目活动是编制进度计划、分析进度状况和控制进度的基本工作包。

常考点：

- 项目活动来源于 WBS 工作包的进一步分解。
- WBS 工作包偏“交付成果”，活动偏“完成成果所需行动”。
- 活动是排序、估算历时、分配资源和进度控制的基础。

容易混淆：

```text
WBS工作包：偏成果/范围。
项目活动：偏行动/执行。
```

### 2.4 进度管理计划的依据（PPT 5）

制定进度管理计划的依据：

1. 项目管理计划。
2. 项目章程。
3. 事业环境因素。
4. 组织过程资产，包括以往项目经验信息、模板、规程、历史数据等。

组织过程资产 vs 事业环境因素：

| 项目 | 含义 | 例子 |
|---|---|---|
| 组织过程资产 | 组织内部积累的经验、模板、制度、历史资料 | 历史项目工期数据、进度模板、管理制度 |
| 事业环境因素 | 项目外部或组织环境中不易由项目团队控制的条件 | 市场环境、组织结构、法规、工具平台、资源市场 |

### 2.5 进度管理计划的主要内容（PPT 5）

进度管理计划是规定如何规划、制定、管理、执行和控制项目进度的文件。

主要包括：

1. 制定项目进度模型，例如项目活动网络图、关键路径等。
2. 准确度要求，例如可接受的估算区间和应急储备。
3. 计量单位，例如人年、人月、人周、人天。
4. 绩效测量规则，例如如何衡量计划与实际的偏差。
5. 报告格式，例如进度报告的内容、频率和模板。
6. 进度更新和变更控制规则。

可能简答问法：

- 进度管理计划主要包括哪些内容？
- 进度管理计划与进度计划有什么区别？

高分答案：

进度管理计划是说明如何管理项目进度的规则性文件，主要包括进度模型、估算准确度、计量单位、绩效测量规则、报告格式以及进度更新和变更控制规则等。它的作用是为后续进度计划制定、执行、监控和变更提供统一依据。进度管理计划强调“如何管进度”，而进度计划强调“具体何时做什么”。

## 3. 活动定义（PPT 6-9）

### 3.1 活动定义的概念（PPT 7）

定义：

活动定义是识别和记录为完成项目可交付成果而需采取的具体行动的过程。

作用：

1. 将 WBS 工作包分解为具体活动。
2. 明确项目执行层面的工作内容。
3. 为活动排序、资源估算、历时估算和进度计划编制打基础。
4. 便于责任分配和进度跟踪。

可能简答问法：

- 什么是活动定义？活动定义的作用是什么？
- 活动定义与 WBS 有什么关系？

高分答案：

活动定义是识别并记录为完成项目可交付成果而需要采取的具体行动的过程。它的作用是把 WBS 中的工作包进一步分解为可执行、可排序、可估算和可控制的活动，从而为后续活动排序、历时估算、资源安排和进度计划编制提供基础。

容易混淆：

- WBS 是范围分解，不是直接的时间安排。
- 活动定义是把范围转化为行动，不是重新定义项目范围。

### 3.2 活动定义的方法：分解（PPT 7）

定义：

分解是基于 WBS，把项目工作包分解成更小、更易于管理的组成部分，即活动。

作用：

1. 提高工作粒度。
2. 便于估算时间和资源。
3. 便于明确责任人。
4. 便于进度检查和控制。

注意：

分解不应无限细化。活动粒度要达到“能估算、能安排、能跟踪、能交付”的程度即可。

### 3.3 活动定义的方法：滚动式规划（PPT 7）

定义：

滚动式规划是指对远期工作进行粗略规划，对近期工作进行详细规划，并随着项目推进逐步细化。

PPT 表述：

```text
远期工作 -> 粗略，如里程碑水平。
近期工作 -> 具体活动。
```

作用：

1. 适合需求逐步明确的软件项目。
2. 避免过早对不确定工作做过细计划。
3. 允许项目在变化中逐步细化安排。
4. 提高计划的现实性和可执行性。

可能简答问法：

- 什么是滚动式规划？
- 为什么软件项目适合滚动式规划？

容易混淆：

滚动式规划不是没有计划，而是“先粗后细、逐步细化”。

### 3.4 活动定义的方法：专家判断（PPT 7）

定义：

专家判断是指借助有经验并擅长制定项目范围说明书、WBS 和项目进度计划的团队成员或其他专家来识别活动。

作用：

1. 利用历史经验提高活动识别质量。
2. 弥补项目早期数据不足。
3. 发现容易遗漏的管理活动、协调活动和风险活动。
4. 提高计划的可行性。

注意：

专家判断不是“拍脑袋”，应结合历史数据、项目环境和团队能力。

### 3.5 活动清单（PPT 8）

定义：

活动清单是活动定义的结果，列出完成项目所需执行的全部活动。

作用：

1. 为活动排序提供输入。
2. 为活动历时估算提供对象。
3. 为资源安排和责任分配提供基础。
4. 为进度控制提供跟踪对象。

常考选填：

```text
活动定义的结果：活动清单、里程碑清单等。
```

### 3.6 里程碑清单（PPT 9）

定义：

里程碑是项目中的重要时点或事件，通常表示阶段完成、关键交付物完成或重要决策点。

PPT 示例：

- 测试计划设计。
- 测试用例设计。
- 测试用例审查。
- 代码完成。
- 集成测试完成。
- 代码冻结。
- 测试结束。
- 测试和质量报告完成。

作用：

1. 标识项目关键节点。
2. 便于阶段性检查和汇报。
3. 便于管理层和干系人理解项目进展。
4. 可作为阶段验收和控制点。

里程碑 vs 活动：

| 对比项  | 里程碑         | 活动          |
| ---- | ----------- | ----------- |
| 本质   | 重要时点或事件     | 一段具体工作      |
| 持续时间 | 通常为0或很短     | 有持续时间       |
| 作用   | 检查点、节点、阶段成果 | 执行、估算和控制对象  |
| 例子   | 代码冻结、测试结束   | 设计测试用例、执行测试 |

可能简答问法：

- 什么是里程碑？举例说明。
- 里程碑清单在进度管理中有什么作用？

## 4. 活动排序（PPT 10-13）

### 4.1 活动排序的概念（PPT 11-12）

定义：

活动排序是识别和记录项目活动之间关系的过程。

作用：

1. 明确哪些活动必须先做，哪些活动可以并行。
2. 确定紧前活动和紧后活动。
3. 形成项目活动网络图。
4. 为关键路径计算、总工期计算和进度风险分析提供依据。

可能简答问法：

- 什么是活动排序？
- 活动排序的结果是什么？
- 活动排序在进度计划中的作用是什么？

高分答案：

活动排序是识别并记录项目活动之间逻辑关系的过程。它通过确定活动的紧前和紧后关系，明确活动之间的先后顺序和依赖关系，形成项目活动网络图。活动排序是计算关键路径、估算项目总工期、识别关键活动和制定进度计划的重要基础。

容易混淆：

```text
活动定义：确定要做哪些活动。
活动排序：确定这些活动之间的先后关系。
活动历时估算：确定每个活动要多久。
制定进度计划：综合顺序、历时、资源和约束形成计划。
```

### 4.2 紧前关系绘图法 PDM（PPT 11）

定义：

紧前关系绘图法（Precedence Diagramming Method, PDM）也称前导图法或优先顺序图法，是用节点表示活动、用箭线表示依赖关系的网络图方法。

四种逻辑关系：

| 关系 | 英文 | 含义 | 例子 |
|---|---|---|---|
| 完成-开始 | FS | 前一活动完成后，后一活动才能开始 | 需求评审完成后开始设计 |
| 开始-开始 | SS | 前一活动开始后，后一活动才能开始 | 开始编码后可同步开始单元测试准备 |
| 完成-完成 | FF | 前一活动完成后，后一活动才能完成 | 文档编写完成后，文档审查才能完成 |
| 开始-完成 | SF | 前一活动开始后，后一活动才能完成 | 新系统上线开始后，旧系统下线才能完成 |

常考选填：

```text
PDM = 紧前关系绘图法 = 前导图法 = 优先顺序图法。
PDM 常见逻辑关系：FS、SS、FF、SF。
最常见的是 FS。
```

容易混淆：

- 不是所有依赖都是“完成-开始”。
- SF 很少见，但考试可能会填空。

### 4.3 项目活动网络图（PPT 12-13）

定义：

项目活动网络图是活动排序的结果，用图形方式表示项目活动及其依赖关系。

作用：

1. 表示活动之间的逻辑关系。
2. 支持关键路径计算。
3. 支持 ES、EF、LS、LF 和时差计算。
4. 帮助识别进度风险和次关键路径。
5. 为进度压缩和资源优化提供依据。

网络图 vs 甘特图：

| 项目 | 网络图 | 甘特图 |
|---|---|---|
| 重点 | 活动逻辑关系 | 时间轴与进度展示 |
| 优势 | 适合关键路径计算 | 直观易懂，便于汇报 |
| 局限 | 不如甘特图直观展示日期 | 不擅长复杂依赖分析 |

## 5. 活动历时估算（PPT 14-17）

### 5.1 活动历时估算的概念（PPT 15）

定义：

活动历时估算是确定完成每个活动所需花费的时间量。

作用：

1. 为进度计划提供活动持续时间。
2. 为关键路径和总工期计算提供基础。
3. 为资源安排和进度控制提供依据。
4. 帮助识别进度风险。

容易混淆：

| 概念 | 含义 |
|---|---|
| 工作量 | 完成工作需要投入的人时/人天 |
| 历时 | 从活动开始到完成经过的日历时间 |

例子：

某活动需要 10 人天工作量。如果 1 人做，可能历时 10 天；如果 2 人并行且无额外沟通损耗，可能历时 5 天。但软件项目中人力增加并不总能线性缩短历时。

### 5.2 历时估算的依据（PPT 15）

PPT 列出的依据：

1. 活动清单和活动属性。
2. 项目约束和假设条件。
3. 资源情况和资源数量。
4. 资源能力和质量，如 IT 项目中的人力资源技术/管理水平。
5. 历史信息。
6. 风险登记册。

可能简答问法：

- 活动历时估算需要考虑哪些依据？
- 为什么资源能力会影响活动历时？

高分答案：

活动历时估算需要综合考虑活动清单和活动属性、项目约束和假设条件、资源数量、资源能力、历史信息以及风险登记册等因素。因为同一活动在不同资源数量、人员能力、技术难度和风险条件下所需时间不同，所以历时估算不能只看任务名称，还要结合实际执行条件。

### 5.3 专家判断（PPT 16）

定义：

专家判断是借助有经验人员对活动持续时间进行估计。

适用场景：

1. 项目早期缺少详细数据。
2. 活动具有创新性或复杂性。
3. 历史项目数据不完全适用。
4. 需要结合团队能力和环境条件综合判断。

缺点：

容易受专家经验范围、乐观偏差和主观判断影响。因此最好结合历史数据和其他估算方法。

### 5.4 类比估算（PPT 16）

定义：

类比估算以过去类似项目或活动的实际持续时间为依据，估算当前项目活动持续时间。

特点：

1. 速度快。
2. 成本低。
3. 精度相对较粗。
4. 依赖历史项目与当前项目的相似程度。

适用场景：

项目早期信息不足、需要快速估算、活动与历史项目相似。

可能简答问法：

- 什么是类比估算？它有什么优缺点？

答案：

类比估算是根据过去类似项目或活动的实际持续时间来估算当前活动持续时间的方法。它的优点是快速、成本低，适合项目早期粗略估算；缺点是依赖历史项目相似性，精度较低，若项目差异较大容易估算失真。

### 5.5 参数估算（PPT 16）

定义：

参数估算是利用历史数据和参数关系进行估算的方法。

PPT 示例：

在软件项目中，将某个模块的代码行数乘以每行代码所需的工作量，就可以得到该模块活动的持续时间或工作量估计。

常见形式：

```text
活动工作量 = 工作规模 × 单位规模工作量
活动历时 = 活动工作量 / 可投入资源能力
```

例子：

```text
预计模块 1000 行代码，历史效率为每人每天 100 行。
工作量 = 1000 / 100 = 10 人天。
若安排 2 人并行且效率不损失，历时约 5 天。
```

注意：

参数估算比类比估算更量化，但前提是参数模型可靠。

### 5.6 三点估算（PPT 17）

定义：

三点估算使用三个估算值来界定活动历时的近似区间：

1. 最乐观时间 TO：基于最好情况估算的活动历时。
2. 最可能时间 TM：基于较现实情况估算的活动历时。
3. 最悲观时间 TP：基于最差情况估算的活动历时。

公式：

```text
活动持续时间 TE = (TO + 4TM + TP) / 6
标准差 = (TP - TO) / 6
```

记忆：

```text
最可能时间 TM 权重最大，占4份。
不是简单平均。
```

例题：

```text
TO = 4天，TM = 7天，TP = 16天。
TE = (4 + 4×7 + 16) / 6 = 48 / 6 = 8天。
标准差 = (16 - 4) / 6 = 2天。
可写作：8天 ± 2天。
```

可能简答/计算问法：

- 三点估算中的三个时间分别是什么？
- 已知 TO、TM、TP，求 TE 和标准差。
- 为什么三点估算比单点估算更合理？

高分答案：

三点估算通过最乐观、最可能、最悲观三个时间值考虑活动历时的不确定性，并用加权公式计算期望历时。与单点估算相比，它能体现风险和波动范围，因此更适合不确定性较高的软件项目活动估算。

## 6. 制定进度计划（PPT 18-32）

### 6.1 制定进度计划的概念（PPT 19）

定义：

制定进度计划是分析活动顺序、持续时间、资源需求和进度制约因素，创建项目进度模型的过程。

需要分析的因素：

1. 活动顺序。
2. 活动持续时间。
3. 资源需求。
4. 进度制约因素。
5. 项目日历、资源日历和里程碑约束。
6. 风险和不确定性。

可能简答问法：

- 什么是制定进度计划？
- 制定进度计划需要综合分析哪些因素？

高分答案：

制定进度计划是综合分析活动顺序、持续时间、资源需求和进度制约因素，创建项目进度模型的过程。它不是简单地排列日期，而是要在活动依赖关系、资源条件、工期目标和项目约束之间进行平衡，形成可执行、可跟踪和可控制的进度安排。

### 6.2 关键路径法 CPM（PPT 19-25）

定义：

关键路径法（Critical Path Method, CPM）是通过项目活动网络确定关键路径并计算项目总工期的方法。

关键路径：

关键路径是项目活动网络中总历时最长的路径，它决定项目的最短完成时间。

关键活动：

关键路径上的活动通常称为关键活动。关键活动的总时差通常为 0，其延误会直接导致项目总工期延误。

作用：

1. 计算项目最短总工期。
2. 识别关键活动。
3. 计算各活动的 ES、EF、LS、LF。
4. 计算活动时差。
5. 指导进度控制和进度压缩。

容易混淆：

```text
关键路径不是活动数量最多的路径，而是总历时最长的路径。
关键路径可能不止一条。
关键路径会随着进度变化和压缩调整而变化。
```

### 6.3 ES、EF、LS、LF（PPT 21）

四个时间：

| 缩写 | 中文 | 含义 |
|---|---|---|
| ES | 最早开始时间 | 在不违反依赖关系下活动最早能开始的时间 |
| EF | 最早完成时间 | 活动最早能完成的时间 |
| LS | 最晚开始时间 | 不影响项目工期前提下活动最晚能开始的时间 |
| LF | 最晚完成时间 | 不影响项目工期前提下活动最晚能完成的时间 |

正推规则：

```text
起点 ES = 0。
活动 ES = 所有紧前活动 EF 的最大值。
活动 EF = ES + 活动历时。
项目最早完成时间 = 最后节点 EF。
```

反推规则：

```text
若没有明确项目最晚完成时间，则项目 LF = 项目最早完成时间。
若合同期限为 tp，则项目 LF = tp。
活动 LF = 所有紧后活动 LS 的最小值。
活动 LS = LF - 活动历时。
```

时差：

```text
总时差 TF = LS - ES = LF - EF。
TF = 0 的活动通常为关键活动。
```

常见失分点：

1. 正推时取紧前活动 EF 的最大值，而不是最小值。
2. 反推时取紧后活动 LS 的最小值，而不是最大值。
3. 忘记写时差。
4. 把关键路径写成活动集合而不是从起点到终点的一条路径。

### 6.4 PPT 例题：关键路径计算模板（PPT 23）

PPT 第23页网络图：

```text
开始 -> A(2), B(6), C(4)
A -> F(7)
B -> D(3), E(5)
C -> E(5)
D -> F(7), G(2)
E -> G(2)
F, G -> 结束
```

正推：

| 活动 | 历时 | ES | EF | 说明 |
|---|---:|---:|---:|---|
| A | 2 | 0 | 2 | 起点活动 |
| B | 6 | 0 | 6 | 起点活动 |
| C | 4 | 0 | 4 | 起点活动 |
| D | 3 | 6 | 9 | B 后续 |
| E | 5 | 6 | 11 | max(B=6, C=4) |
| F | 7 | 9 | 16 | max(A=2, D=9) |
| G | 2 | 11 | 13 | max(D=9, E=11) |

项目最早完成时间：

```text
max(F EF=16, G EF=13) = 16
```

反推（无合同期限时，项目 LF = 16）：

| 活动 | 历时 | LS | LF | 说明 |
|---|---:|---:|---:|---|
| F | 7 | 9 | 16 | 终点前活动 |
| G | 2 | 14 | 16 | 终点前活动 |
| D | 3 | 6 | 9 | min(F LS=9, G LS=14) |
| E | 5 | 9 | 14 | G 前置 |
| A | 2 | 7 | 9 | F 前置 |
| B | 6 | 0 | 6 | min(D LS=6, E LS=9) |
| C | 4 | 5 | 9 | E 前置 |

总时差：

| 活动 | ES | EF | LS | LF | TF |
|---|---:|---:|---:|---:|---:|
| A | 0 | 2 | 7 | 9 | 7 |
| B | 0 | 6 | 0 | 6 | 0 |
| C | 0 | 4 | 5 | 9 | 5 |
| D | 6 | 9 | 6 | 9 | 0 |
| E | 6 | 11 | 9 | 14 | 3 |
| F | 9 | 16 | 9 | 16 | 0 |
| G | 11 | 13 | 14 | 16 | 3 |

关键路径：

```text
B -> D -> F
总工期 = 6 + 3 + 7 = 16天。
```

### 6.5 合同工期给定时的反推（PPT 24）

PPT 问法：

如果项目合同工期为 18 天，求每个活动的最晚开始时间和最晚结束时间。

处理方法：

```text
项目最终期限 tp = 18。
令项目 LF = 18。
从终点开始反推各活动 LF 和 LS。
```

以上 PPT 第23页网络图若合同工期为 18 天：

| 活动 | 历时 | LS | LF | TF = LS - ES |
|---|---:|---:|---:|---:|
| F | 7 | 11 | 18 | 11 - 9 = 2 |
| G | 2 | 16 | 18 | 16 - 11 = 5 |
| D | 3 | 8 | 11 | 8 - 6 = 2 |
| E | 5 | 11 | 16 | 11 - 6 = 5 |
| A | 2 | 9 | 11 | 9 - 0 = 9 |
| B | 6 | 2 | 8 | 2 - 0 = 2 |
| C | 4 | 7 | 11 | 7 - 0 = 7 |

注意：

当合同工期大于最早完工时间时，项目整体有缓冲时间；关键活动的时差也可能不再为0，但原始网络中决定最早完工的路径仍是最长路径。

### 6.6 资源受限进度安排（PPT 25）

PPT 提到：

资源受限（例如 10 人）情况下，可以尝试：

1. 最长历时优先安排。
2. 最短历时优先安排。
3. 思考怎样优先安排可使总进度最短。

定义：

资源受限进度安排是在资源数量有限时，对活动开始时间进行调整，使资源需求不超过可用资源。

答题步骤：

1. 先根据网络图找出可并行活动。
2. 检查同一时间段资源需求是否超过上限。
3. 若超过资源上限，则按优先规则安排活动。
4. 常见优先规则包括关键活动优先、总时差小优先、最长历时优先、最短历时优先。
5. 调整后重新计算总工期。

容易混淆：

- CPM 默认资源可用，不一定考虑资源上限。
- 资源受限后，实际工期可能长于关键路径法计算出的理论最短工期。

## 7. 资源优化、进度压缩与关键链（PPT 26-28）

### 7.1 资源优化（PPT 26）

定义：

资源优化用于调整活动的开始和完成日期，以调整计划使用的资源，使其等于或少于可用资源。

包括：

1. 资源平衡。
2. 资源平滑。

资源平衡：

当资源过度分配或资源不足时，调整活动时间以解决资源冲突。资源平衡可能改变关键路径和项目总工期。

资源平滑：

在不改变关键路径和项目总工期的前提下，利用活动浮动时间调整资源使用，使资源需求更平稳。

对比：

| 项目 | 资源平衡 | 资源平滑 |
|---|---|---|
| 目的 | 解决资源不足/过载 | 让资源使用更均衡 |
| 是否可能改变工期 | 可能改变 | 通常不改变 |
| 是否可能改变关键路径 | 可能 | 通常不改变 |
| 调整范围 | 可突破原有浮动时间 | 通常在浮动时间内 |

可能简答问法：

- 什么是资源优化？
- 资源平衡和资源平滑有什么区别？

### 7.2 进度压缩（PPT 27）

定义：

进度压缩是在不缩减项目范围的前提下，缩短或加快进度工期，以满足进度制约因素、强制日期或其他进度目标。

常用方法：

1. 赶工：增加资源或成本来缩短关键路径活动工期。
2. 快速跟进：将原本顺序执行的活动改为部分并行执行。

赶工特点：

- 通常增加成本。
- 应优先压缩关键路径上的活动。
- 应选择单位时间赶工成本较低的活动。
- 压缩后要重新检查关键路径是否变化。

快速跟进特点：

- 通常增加返工风险和沟通风险。
- 不一定明显增加直接成本。
- 适用于活动之间存在一定可重叠空间的情况。

进度压缩不是：

```text
不是删除功能。
不是降低范围。
不是不顾质量地赶进度。
```

可能简答问法：

- 什么是进度压缩？
- 进度压缩与范围缩减有什么区别？
- 赶工与快速跟进有什么区别？

### 7.3 赶工成本计算

公式：

```text
单位时间赶工成本 = (赶工费用 - 正常费用) / (正常工期 - 赶工工期)
```

答题步骤：

1. 先找关键路径。
2. 只优先考虑关键路径上的活动。
3. 计算关键路径上各可压缩活动的单位时间赶工成本。
4. 选择单位时间赶工成本最低的活动先压缩。
5. 每压缩一次后，重新判断关键路径是否变化。

去年试卷同类题答案逻辑：

```text
关键路径：A -> D -> E -> F -> H
只能优先压缩关键路径上的活动。
比较 A、D、E、F、H 的单位时间赶工成本。
选择单位时间赶工成本最低的 F 活动优先压缩。
```

### 7.4 帕金森定律（PPT 28）

PPT 表述：

帕金森定律：拖延症。

扩展理解：

帕金森定律在项目管理中通常表示：工作会膨胀以填满可用时间。也就是说，如果给某项任务预留过多时间，任务并不一定提前完成，反而可能因为拖延、等待和过度加工而消耗掉全部时间。

在软件项目中的表现：

1. 开发人员会把个人安全时间消耗掉。
2. 任务看似有余量，但最后仍在截止日前集中完成。
3. 前期拖延导致后期集成、测试和修复压力增加。
4. 个人缓冲分散在各活动中，难以由项目经理统一调度。

### 7.5 关键链法（PPT 28）

PPT 表述：

关键路径法是工作安排尽早开始，尽可能提前；关键链法是尽可能推迟，空出时间作为项目 buffer 时间。

解决办法：

压缩时间估算，增加安全备用时间，作为公共资源统一调度，用到真正需要的地方，可大大缩短工期。

关键链法核心：

1. 不只考虑活动逻辑关系，还考虑资源约束。
2. 压缩单个活动中过多的安全时间。
3. 将安全时间集中为项目缓冲或接驳缓冲。
4. 通过缓冲消耗情况监控项目风险。
5. 目标是减少拖延和多任务切换，提高整体进度可靠性。

关键路径法 vs 关键链法：

| 对比项 | 关键路径法 CPM | 关键链法 CCM |
|---|---|---|
| 关注重点 | 活动逻辑关系和最长路径 | 逻辑关系 + 资源约束 + 缓冲 |
| 安排倾向 | 尽早开始 | 在可控范围内尽量推迟 |
| 安全时间 | 分散在各活动估算中 | 集中为公共 buffer |
| 控制重点 | 关键活动是否延误 | buffer 消耗和资源冲突 |

可能简答问法：

- 关键链法与关键路径法有什么区别？
- 关键链法为什么能缩短工期？
- 帕金森定律对项目进度有什么影响？

高分答案：

关键链法是在关键路径法基础上进一步考虑资源约束和缓冲管理的方法。关键路径法主要依据活动逻辑关系计算最长路径，并倾向于尽早安排活动；关键链法则压缩单项活动中过多的安全时间，将安全时间集中为项目 buffer 统一管理，并通过监控 buffer 消耗来控制进度风险。它可以减少拖延和安全时间浪费，提高进度计划的整体可靠性。

## 8. 项目进度计划成果（PPT 29-32）

### 8.1 甘特图（PPT 29-30）

定义：

甘特图是用横向条形图在时间轴上表示活动开始时间、结束时间、持续时间和进展情况的工具。

作用：

1. 直观展示任务的起止时间。
2. 便于查看任务持续时间和重叠情况。
3. 便于向团队和干系人沟通计划。
4. 便于跟踪实际进度和计划进度的差异。

优点：

- 直观。
- 易理解。
- 适合汇报。
- 适合展示计划和实际进度。

局限：

- 不擅长表达复杂依赖关系。
- 对关键路径和时差分析不如网络图。

可能简答问法：

- 甘特图有什么特点？
- WBS 与甘特图有什么异同？

WBS vs 甘特图（参考去年卷对比题）：

| 对比项 | WBS | 甘特图 |
|---|---|---|
| 共同点 | 都是项目管理重要工具；都帮助任务划分、计划和协调 |
| 关注点 | 项目范围和工作分解 | 任务时间安排和进度跟踪 |
| 表现形式 | 树状结构或层级列表 | 时间轴条形图 |
| 使用阶段 | 偏前期范围定义和规划 | 偏计划展示、执行跟踪和调整 |
| 优势 | 明确项目范围，避免遗漏工作 | 直观展示进度，便于沟通和控制 |

高分答案：

WBS 和甘特图都是软件项目管理中的重要工具，都有助于任务划分、资源协调和项目控制。不同的是，WBS 主要用于将项目分解为更小、更易管理的工作单元，强调项目范围和交付成果；甘特图则用条形时间图展示任务的开始时间、结束时间和持续时间，强调时间安排和进度跟踪。WBS 通常用于项目早期规划，甘特图更多用于进度计划展示、执行监控和计划调整。

### 8.2 里程碑图（PPT 31）

定义：

里程碑图是突出显示项目关键事件、重要节点和阶段成果的进度图。

作用：

1. 便于高层和干系人快速了解关键进展。
2. 适合项目汇报和阶段验收。
3. 适合展示发布计划、评审节点和交付节点。
4. 帮助项目经理抓住关键控制点。

里程碑图 vs 甘特图：

| 项目 | 里程碑图 | 甘特图 |
|---|---|---|
| 展示粒度 | 较粗 | 较细 |
| 重点 | 关键节点 | 活动持续时间 |
| 使用对象 | 高层、客户、干系人 | 项目经理、团队成员 |
| 适合场景 | 汇报和验收 | 计划和跟踪 |

### 8.3 进度基准（PPT 31）

定义：

进度基准是经过批准的进度计划，用作与实际结果进行比较的依据。

关键词：

```text
经过批准
用于比较
用于控制
变更需要正式管理
```

作用：

1. 为进度控制提供比较标准。
2. 支持偏差分析和趋势分析。
3. 支持绩效评价。
4. 支持进度变更控制。

进度计划 vs 进度基准：

| 项目 | 进度计划 | 进度基准 |
|---|---|---|
| 含义 | 项目时间安排 | 经批准用于比较的进度计划 |
| 是否可随意更新 | 可根据管理需要更新 | 变更需正式批准 |
| 作用 | 指导执行 | 控制和评价依据 |

### 8.4 提高进度计划/基准效能（PPT 32）

PPT 要点：

1. 项目经理首先自己要重视项目进度计划，不能敷衍了事。
2. 项目经理一定要让团队成员参与项目进度计划的制定管理。
3. 项目进度计划要详略得当、层次分明，并且要考虑不同职能部门的实际需要。
4. 项目进度计划要及时更新，并以适当频度对外发布。

扩展理解：

进度计划不是为了提交文档，而是为了指导执行。若项目经理不重视、团队不参与、计划粒度不合适或更新不及时，计划就会与实际脱节，无法发挥控制作用。

可能简答问法：

- 如何提高项目进度计划的效能？
- 为什么进度计划需要团队成员参与？

高分答案：

提高进度计划效能需要项目经理重视计划，将其作为项目执行和控制的基础；让团队成员参与制定，以提高估算准确性和执行认同；计划要详略得当、层次分明，并考虑不同职能部门的需要；同时要根据项目实际及时更新，并以适当频度向相关人员发布，确保计划始终能够指导执行。

## 9. 进度控制（PPT 33-37）

### 9.1 软件项目进度失控原因：80-20原则与过于乐观（PPT 34）

PPT 表述：

80%的项目工作可以在20%的时间内完成，而剩余20%的项目工作需要80%的时间。

含义：

软件项目进入编码阶段后，表面上可能进展很快，使项目经理、团队成员、用户和高层领导产生过于乐观的估计。但后期集成、测试、缺陷修复、兼容性问题、文档和收尾工作往往耗时巨大。

表现：

1. 前期进展看似顺利。
2. 后期问题集中暴露。
3. 缺陷修复和集成测试反复返工。
4. 管理者误以为项目接近完成。
5. 最后20%的工作消耗大量时间。

常考选填：

```text
80-20原则：80%的项目工作可能在20%的时间完成，剩余20%的工作需要80%的时间。
```

容易混淆：

这里的 80-20 是进度控制中的乐观偏差现象，不要机械等同于质量管理中的帕累托分析。

### 9.2 范围、质量、资源、预算变更对进度的影响（PPT 34）

导致进度失控的因素：

1. 范围扩大：需求增加、功能增加、变更频繁。
2. 质量要求提高：测试标准提高、缺陷修复要求提高。
3. 资源变化：人员不足、关键人员离职、设备或工具不到位。
4. 预算变化：预算削减导致资源无法按计划投入。

答题句式：

软件项目进度受到范围、质量、资源和预算等因素共同影响。若需求范围扩大、质量要求提高、资源投入不足或预算发生变化，而进度计划没有及时调整，就会导致原计划与实际执行条件不匹配，从而造成进度失控。

### 9.3 低估软件项目开发实现条件（PPT 35）

PPT 要点：

1. 低估技术难度，本质上也是高估人的能力。
2. 低估工作协调复杂度。
3. 低估环境因素，包括用户环境、行业环境、组织环境、社会环境、经济环境。

扩展：

软件项目不是单纯写代码，进度还受到需求澄清、跨部门沟通、用户反馈、接口协调、部署环境、政策制度和组织决策等因素影响。若计划只按理想开发效率估算，就容易出现进度失控。

可能简答问法：

- 为什么低估实现条件会导致软件项目进度失控？
- 软件项目实现条件包括哪些方面？

### 9.4 项目状态信息收集失真（PPT 35）

PPT 要点：

项目状态信息收集不足，及时性、准确性、完整性较差；某些项目团队成员报喜不报忧。

危害：

1. 项目经理无法及时发现偏差。
2. 问题被延迟暴露。
3. 决策建立在错误信息上。
4. 进度风险无法提前处理。
5. 最终导致集中延期或质量问题。

答题关键词：

```text
及时性
准确性
完整性
报喜不报忧
信息失真
决策失真
```

### 9.5 执行计划不严格、计划调整不及时、未考虑不可预见事件（PPT 36）

执行计划不严格：

没有把计划作为项目过程行动的基础，而是把计划放在一边，随意执行。

计划变更调整不及时：

随着需求细化和设计明确，项目分工和进度没有及时调整，导致进度计划不符合项目变化。

未考虑不可预见事件：

没有为突发事件、风险、人员变动、技术问题等预留缓冲和应对措施。

可能简答问法：

- 软件项目进度失控的原因有哪些？

高分答案：

软件项目进度失控的原因包括：第一，80-20原则导致项目经理和团队对进度过于乐观，低估后期集成、测试和修复工作；第二，范围、质量、资源和预算变化影响原有计划；第三，低估技术难度、协调复杂度和环境因素；第四，项目状态信息收集不及时、不准确、不完整，甚至报喜不报忧；第五，执行计划不严格，计划变更调整不及时，且未充分考虑不可预见事件。

### 9.6 进度控制的概念（PPT 37）

定义：

进度控制包括监督项目活动状态，更新项目进展，管理进度基准变更，以实现计划的过程。本过程提供发现计划偏离的方法，从而及时采取纠正和预防措施，以降低风险。

关键词：

```text
监督活动状态
更新项目进展
管理进度基准变更
发现计划偏离
采取纠正措施
采取预防措施
降低风险
```

可能简答问法：

- 什么是进度控制？
- 进度控制的作用是什么？

高分答案：

进度控制是监督项目活动状态、更新项目进展、管理进度基准变更以实现计划的过程。它的作用是及时发现实际进度与计划之间的偏离，并通过纠正措施和预防措施降低进度风险，保证项目尽可能按批准的进度基准执行。

### 9.7 进度控制方法：偏差分析与趋势分析（PPT 37）

偏差分析：

关注实际开始和完成日期与计划日期的偏离，实际持续时间与计划持续时间的差异，以及浮动时间的偏差。

趋势分析：

检查项目绩效随时间的变化情况，以确定绩效是在改善还是在恶化。

对比：

| 项目 | 偏差分析 | 趋势分析 |
|---|---|---|
| 关注 | 当前差多少 | 未来趋势如何 |
| 对象 | 实际 vs 计划 | 多个时间点的绩效变化 |
| 作用 | 判断偏离程度 | 判断改善或恶化趋势 |

例子：

```text
偏差分析：某活动计划第10天完成，实际第13天完成，偏差3天。
趋势分析：连续三周进度偏差从1天、3天、6天扩大，说明趋势恶化。
```

### 9.8 进度控制方法：关键路径法（PPT 37）

PPT 要点：

评估次关键路径上的活动进展情况，有助于识别进度风险。

扩展：

进度控制不能只盯当前关键路径。次关键路径虽然暂时不是关键路径，但浮动时间较少，一旦延误可能转化为新的关键路径。

答题关键词：

```text
关键路径
关键活动
次关键路径
浮动时间
进度风险
```

### 9.9 进度控制方法：挣值管理（PPT 37）

PPT 要点：

挣值管理采用进度绩效测量指标，评价偏离初始进度基准的程度，并传达给干系人。

理解：

挣值管理是一种综合范围、进度和成本的绩效测量方法。本章只需掌握它在进度控制中的作用：量化项目绩效，评价与进度基准的偏差，并支持沟通和纠偏。

可能简答问法：

- 挣值管理在进度控制中的作用是什么？

答案：

挣值管理通过进度绩效指标评价项目实际绩效偏离进度基准的程度，并将偏差信息传达给干系人。它综合考虑范围、进度和成本，有助于项目经理及时发现进度问题并采取控制措施。

## 10. 计算题专题

### 10.1 关键路径法计算步骤

通用步骤：

1. 根据题目画出或读懂网络图。
2. 正推计算 ES 和 EF。
3. 得到项目最早完成时间。
4. 反推计算 LF 和 LS。
5. 计算总时差 TF。
6. 找出 TF = 0 的关键活动。
7. 写出关键路径和项目总工期。

公式：

```text
EF = ES + 活动历时
ES = 所有紧前活动 EF 的最大值
LS = LF - 活动历时
LF = 所有紧后活动 LS 的最小值
TF = LS - ES = LF - EF
```

答题版式：

```text
正推：
A: ES=0, EF=...
B: ES=..., EF=...

反推：
终点 LF=项目总工期或合同工期。
F: LF=..., LS=...

时差：
TF=LS-ES。

关键路径：
TF=0 的活动组成关键路径：...
总工期：...天。
```

### 10.2 合同工期题

题型：

已知网络图最早完成时间为 16 天，但合同要求最晚 18 天完成，求 LS、LF。

处理：

```text
项目 LF 不再取最早完成时间16，而取合同期限18。
然后反推所有活动。
```

注意：

若合同期限小于最早完成时间，说明原计划无法满足合同要求，需要进度压缩。

### 10.3 赶工/进度压缩题

公式：

```text
单位时间赶工成本 = (赶工费用 - 正常费用) / (正常工期 - 赶工工期)
```

作答逻辑：

1. 找关键路径。
2. 只考虑关键路径上可赶工活动。
3. 算单位时间赶工成本。
4. 选择成本最低者。
5. 说明压缩后要重新判断关键路径。

标准句式：

假设总工期需要缩短，应首先选择关键路径上的活动进行压缩，因为只有压缩关键路径活动才可能缩短项目总工期。然后比较关键路径上各活动的单位时间赶工成本，选择单位时间赶工成本最低的活动优先压缩。每次压缩后应重新计算关键路径，防止关键路径发生变化。

### 10.4 三点估算题

公式：

```text
TE = (TO + 4TM + TP) / 6
标准差 = (TP - TO) / 6
```

答题注意：

1. TO 是最乐观，不是最短路径。
2. TM 是最可能，权重为4。
3. TP 是最悲观。
4. 结果可以写成“TE ± 标准差”。

### 10.5 资源受限题

作答步骤：

1. 按网络图列出每个时间段可安排活动。
2. 检查活动并行时资源需求是否超过上限。
3. 超过上限时，根据题目指定规则选择活动。
4. 若题目未指定，可说明常用规则：关键活动优先、总时差小优先、最长历时优先、最短历时优先。
5. 画出调整后的进度安排并计算总工期。

### 10.6 决策树/期望收益 EMV（去年考过，非本章核心但建议保留）

公式：

```text
EMV = Σ(概率 × 收益)
```

去年题型：

```text
甲方案 EMV = 0.2×20 + 0.3×70 + 0.5×100 = 75
乙方案 EMV = 0.3×10 + 0.2×50 + 0.5×160 = 93
乙方案更大，所以选择乙方案。
```

答题步骤：

1. 列出方案和状态。
2. 分别计算每个方案 EMV。
3. 比较 EMV。
4. 选择 EMV 较大的方案。

## 11. 可能简答题题库与标准答案

### 11.1 什么是项目进度管理？

项目进度管理又称项目时间管理，是为保证项目各项工作及项目总任务按时完成所需要的一系列工作与过程。它包括进度管理规划、活动定义、活动排序、活动历时估算、制定进度计划和进度控制等内容。其作用是明确项目活动、安排活动顺序和持续时间、建立进度基准，并在执行过程中发现偏差、采取纠正和预防措施，从而保障项目按期交付。

### 11.2 进度管理计划主要包括哪些内容？

进度管理计划是说明如何规划、制定、管理、执行和控制项目进度的文件。它主要包括项目进度模型、估算准确度、计量单位、绩效测量规则、报告格式以及进度更新和变更控制规则等内容。它为后续进度计划制定、执行和控制提供统一依据。

### 11.3 活动定义的方法有哪些？

活动定义是识别和记录为完成项目可交付成果而需采取的具体行动的过程。常用方法包括：第一，分解，即基于 WBS 将工作包分解为更小、更易管理的活动；第二，滚动式规划，即近期工作详细规划、远期工作粗略规划，并随项目推进逐步细化；第三，专家判断，即借助有经验的项目成员或专家识别活动，减少遗漏并提高计划可行性。

### 11.4 什么是活动排序？其结果是什么？

活动排序是识别和记录项目活动之间关系的过程。它通过确定活动之间的紧前、紧后和依赖关系，明确哪些活动必须先做、哪些活动可以并行。活动排序的主要结果是项目活动网络图，该图可用于关键路径计算、总工期估算、时差计算和进度风险识别。

### 11.5 什么是 PDM？包括哪些逻辑关系？

PDM 即紧前关系绘图法，也称前导图法或优先顺序图法，是用节点表示活动、箭线表示活动依赖关系的网络图方法。它包括四种逻辑关系：完成-开始 FS、开始-开始 SS、完成-完成 FF、开始-完成 SF。其中 FS 最常见，即前一活动完成后后一活动才能开始。

### 11.6 活动历时估算的依据有哪些？

活动历时估算是确定完成每个活动所需时间量的过程。其依据包括活动清单和活动属性、项目约束和假设条件、资源数量、资源能力和质量、历史信息以及风险登记册。估算时需要综合考虑任务本身、资源投入、人员能力、历史经验和风险不确定性。

### 11.7 活动历时估算的方法有哪些？

活动历时估算方法包括专家判断、类比估算、参数估算和三点估算。专家判断依靠经验人员估计；类比估算基于过去类似项目的实际持续时间，速度快但较粗略；参数估算利用历史数据和参数关系进行量化估算；三点估算通过最乐观、最可能和最悲观时间计算期望历时，能体现不确定性和风险。

### 11.8 什么是三点估算？

三点估算是用最乐观时间 TO、最可能时间 TM 和最悲观时间 TP 来估计活动历时的方法。其期望历时公式为 TE=(TO+4TM+TP)/6，标准差为 (TP-TO)/6。它比单点估算更能反映活动的不确定性，适用于风险和波动较大的软件项目活动估算。

### 11.9 什么是关键路径法？

关键路径法是通过项目活动网络确定关键路径并计算项目总工期的方法。关键路径是网络图中总历时最长的路径，它决定项目的最短完成时间。关键路径上的活动通常总时差为0，若这些活动延误，项目总工期通常会延误。关键路径法可用于计算 ES、EF、LS、LF、时差，并指导进度控制和进度压缩。

### 11.10 如何计算 ES、EF、LS、LF？

ES 是最早开始时间，EF 是最早完成时间，LS 是最晚开始时间，LF 是最晚完成时间。正推时，活动 ES 等于所有紧前活动 EF 的最大值，EF=ES+活动历时；反推时，若无明确最终期限，项目 LF 等于项目最早完成时间，活动 LF 等于所有紧后活动 LS 的最小值，LS=LF-活动历时。总时差 TF=LS-ES=LF-EF。

### 11.11 什么是资源优化？

资源优化是通过调整活动的开始和完成日期，使计划使用的资源等于或少于可用资源的技术。资源优化包括资源平衡和资源平滑。资源平衡用于解决资源不足或过载，可能改变关键路径和总工期；资源平滑通常在活动浮动时间内调整资源使用，尽量不改变总工期。

### 11.12 什么是进度压缩？

进度压缩是在不缩减项目范围的前提下，缩短或加快项目工期，以满足强制日期、合同期限或进度目标的方法。常见方式包括赶工和快速跟进。赶工通常通过增加资源或成本压缩关键路径活动，快速跟进则将原本顺序执行的活动改为部分并行执行。进度压缩可能增加成本、风险或返工。

### 11.13 关键路径法和关键链法有什么区别？

关键路径法主要根据活动逻辑关系确定最长路径和项目最短工期，通常倾向于让活动尽早开始。关键链法在关键路径法基础上考虑资源约束和缓冲管理，压缩单项活动中过多的安全时间，并将安全时间集中为项目 buffer 统一调度。关键链法强调通过公共缓冲和资源约束管理减少拖延，提高整体进度可靠性。

### 11.14 什么是进度基准？

进度基准是经过批准的进度计划，用作与实际结果进行比较的依据。它是进度控制、偏差分析、趋势分析和绩效评价的标准。普通进度计划可以根据管理需要更新，而进度基准的变更通常需要经过正式变更控制。

### 11.15 如何提高进度计划的效能？

提高进度计划效能需要项目经理重视进度计划，将其作为项目执行和控制的基础；让团队成员参与计划制定，提高估算准确性和执行认同；计划应详略得当、层次分明，并考虑不同职能部门的实际需要；同时要及时更新，并以适当频度向相关人员发布，使计划始终能够指导实际工作。

### 11.16 软件项目进度失控的原因有哪些？

软件项目进度失控的原因包括：第一，80-20原则和过于乐观的进度估计，导致低估后期工作；第二，范围、质量、资源和预算变化对进度产生影响；第三，低估技术难度、协调复杂度和环境因素；第四，项目状态信息收集不及时、不准确、不完整，甚至报喜不报忧；第五，执行计划不严格、计划变更调整不及时，且未充分考虑不可预见事件。

### 11.17 什么是进度控制？方法有哪些？

进度控制是监督项目活动状态、更新项目进展、管理进度基准变更以实现计划的过程。其作用是发现实际进度与计划之间的偏离，并及时采取纠正和预防措施，降低进度风险。常用方法包括偏差和趋势分析、关键路径法以及挣值管理。

### 11.18 偏差分析和趋势分析有什么区别？

偏差分析关注实际开始和完成日期与计划日期的偏离、实际持续时间与计划持续时间的差异以及浮动时间的偏差，回答“现在偏离多少”。趋势分析关注项目绩效随时间的变化情况，判断绩效是在改善还是恶化，回答“未来可能怎样发展”。二者结合可以帮助项目经理及时发现问题并预测风险。

## 14. 最后背诵版：一页压缩口诀

进度管理流程：

```text
规划规则 -> 定义活动 -> 排活动顺序 -> 估活动历时 -> 制定进度计划 -> 控制进度偏差
```

活动定义：

```text
WBS工作包 -> 活动
方法：分解、滚动式规划、专家判断
结果：活动清单、里程碑清单
```

活动排序：

```text
识别活动关系 -> 紧前/紧后 -> 网络图
PDM四关系：FS、SS、FF、SF
```

历时估算：

```text
依据：活动、约束、资源数量、资源能力、历史信息、风险
方法：专家、类比、参数、三点
三点：TE=(TO+4TM+TP)/6
```

关键路径：

```text
正推：ES取紧前EF最大，EF=ES+历时
反推：LF取紧后LS最小，LS=LF-历时
时差：TF=LS-ES=LF-EF
TF=0 -> 关键活动
最长路径 -> 关键路径
```

进度优化：

```text
资源优化：资源平衡、资源平滑
进度压缩：赶工、快速跟进
赶工先压关键路径上单位赶工成本最低活动
```

进度控制：

```text
监督状态、更新进展、管理基准变更
方法：偏差和趋势分析、关键路径法、挣值管理
失控原因：乐观估计、变更影响、低估条件、信息失真、执行不严、调整不及时、未考虑突发事件
```
