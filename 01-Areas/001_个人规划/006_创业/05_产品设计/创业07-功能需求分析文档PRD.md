# 功能需求文档（PRD）：常工鲜生小程序产品需求

> **文档版本**：v1.0 | **创建日期**：2026-03-14 | **项目**：常工鲜生C2F校园鲜果

---

## 一、产品概述

### 1.1 产品定义

**产品名称**：常工鲜生 (C-G Fresh)

**产品定位**：面向常工院大学生的校园鲜果C2F+轻量化O2O服务平台

**核心价值**："产地直达+校内即时配送"，让大学生享受"更新鲜、更便宜、更便捷"的水果消费体验

### 1.2 业务核心逻辑 (C2F Loop)

```
1. 日间/晚间预售：用户下单（先款），锁定需求
        ↓
2. 凌晨截单汇总：系统自动统计各SKU总量
        ↓
3. 清晨进货分拨：凌家塘/果园拿货后，按楼栋一键生成分拣单
        ↓
4. 午后/傍晚配送：兼职同学扫码核销，宿舍精准交付
```

## 二、用户角色与权限

### 2.1 角色定义

| 角色 | 权限 | 说明 |
|------|------|------|
| **普通用户** | 浏览、下单、支付、评价 | 消费者 |
| **配送员** | 扫码核销、查看配送任务 | 兼职学生 |
| **管理员** | 全部权限 | 创业者本人 |

### 2.2 用户端功能模块

| 模块 | 功能描述 |
|------|----------|
| 首页 | 动态预售位、倒计时器、今日推荐 |
| 分类 | 按果品规格分类（按斤、按盒、拼盘） |
| 购物车 | 商品选择、数量调整 |
| 订单 | 订单状态流：待分拣→配送中→已送达 |
| 我的 | 个人信息、地址管理、会员中心 |

## 三、功能模块设计

### 3.1 用户端 (Client-side)

#### 3.1.1 首页 (Home)

| 功能 | 描述 |
|------|------|
| **动态预售位** | 顶部滚动展示"今日果园直达"（如：万绥草莓） |
| **倒计时器** | 距离今日截单还剩 `XX:XX:XX`（制造紧迫感） |
| **今日推荐** | 热销水果推荐 |

#### 3.1.2 分类页 (Category)

| 功能 | 描述 |
|------|------|
| **品类筛选** | 按果品规格分类（按斤、按盒、拼盘） |
| **搜索** | 关键词搜索水果名称 |
| **筛选** | 按价格、按销量、按新品 |

#### 3.1.3 下单流 (Checkout)

| 功能 | 描述 |
|------|------|
| **宿舍定位** | 预设常工院辽河路/三井校区楼栋列表（如：16号楼-A座） |
| **虚拟号保护** | 保护同学隐私，仅显示姓氏和宿舍号 |
| **支付方式** | 微信支付 |
| **备注** | 顾客可添加配送时间备注 |

#### 3.1.4 订单中心

| 功能 | 描述 |
|------|------|
| **状态流** | 待分拣 → 配送中 → 已送达 |
| **核销二维码** | 配送员扫码核销 |
| **售后入口** | 申请退款/售后 |

### 3.2 配送/管理端 (Admin-side)

> 建议做在同一个小程序内，通过 OpenID 判断权限

#### 3.2.1 进货看板 (C2F Core)

| 功能 | 描述 |
|------|------|
| **一键导出** | 生成当日采购总表（SKU名称 | 总量 | 单位） |
| **供应商管理** | 记录各供应商报价 |

#### 3.2.2 分拣辅助

| 功能 | 描述 |
|------|------|
| **楼栋汇总** | 展示每栋楼的订单分布 |
| **分拣清单** | 按楼栋一键打印清单 |
| **库存预警** | 低库存自动提醒 |

#### 3.2.3 配送核销

| 功能 | 描述 |
|------|------|
| **扫码器** | 配送员送达宿舍后，扫描学生订单二维码 |
| **状态变更** | 状态瞬间变更为"已签收" |
| **配送统计** | 配送员工作量统计 |

## 八、避坑指南

> **技术提醒**：

1. **支付路径**
   - 确认主体（个人/个体户/学校双创中心）能开通微信支付
   - 如果个人主体不行，先用"入驻创业园"后拿到的**营业执照办企业号**

2. **冷启动**
   - 第一周建议在后端手动把"库存"设小
   - 制造供不应求的视觉假象
   - 降低跑凌家塘的备货风险

3. **图片优化**
   - 所有水果图上云前通过Canvas进行压测裁剪
   - 控制在100KB以内
