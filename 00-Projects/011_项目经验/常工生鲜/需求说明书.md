# 智能水果全链路协同平台 - 完整需求说明书

> 版本：v2.0 | 更新日期：2026-04-14 | 制定者：代可行
> 基于 Scrum + Vibe Coding 个人团队开发工作流 v1.0

---

## 一、项目愿景

**一句话：** 一个以"周"为运营节奏、零库存压力的校园水果预售平台，由 AI Agent 驱动采购、存储、销售、配送、客服、财务的全链路自动化。

**核心差异化：**
- 预售制（先卖后采）→ 零库存损耗
- AI Agent 承担采购决策、库存预警、财务日报、客服应答
- 微信小程序作为唯一用户入口，极低上手门槛
- 本地化 AI 部署，生产环境成本极低

---

## 二、系统用户角色

| 角色 | 核心诉求 | 技术入口 |
|------|---------|---------|
| **用户（学生/教职工）** | 刷到想吃的水果 → 下单 → 收货 | 微信小程序 |
| **骑手（兼职学生）** | 抢单 → 取货 → 配送 → 核验 | 小程序骑手模式（角色切换） |
| **采购（运营者本人）** | 拍照录入 → 填写采购价 → 上架 | 小程序工作台（扫码授权） |
| **管理员（运营者本人）** | 订单监控、价格调整、AI报表 | Web 后台（统一管理中心） |

> **角色切换策略：** 所有角色复用同一套微信账号体系，通过权限字段控制功能可见性。

## 三、核心业务流程（4个场景）

### Scene 1：采购（采购员视角）

```
拍照/手动录入水果信息
    ↓
填写：品名、等级、产地、采购价、建议售价、毛利率、上架时间
    ↓
系统自动生成：
  - 冷藏建议（根据时节、水果类型）
  - 文案（AI生成，水果店风格）
  - 采购List导出（权重、名称、产地、储存建议）
    ↓
水果上架 → 进入库存待发状态
```

**AI 介入点：**
- 自动提取图片品名（多模态模型）
- 冷藏建议生成（智果博士 Agent）
- 商品文案生成（农创·灵感 Agent）

---

### Scene 2：存储（系统自动处理）

```
到货确认
    ↓
库存状态更新 → 首页推荐同步
    ↓
骑手可抢单（订单状态：待取货）
    ↓
库存预警阈值触发 → 自动通知采购补货
```

**AI 介入点：**
- 库存预警 Agent（低于阈值自动发微信推送）
- 首页推荐算法（基于历史购买数据）

---

### Scene 3：下单（用户视角）

```
首页浏览瀑布流（按上架时间/销量/折扣排序）
    ↓
选择商品（预订/现货）→ 加入购物车
    ↓
填写：配送地址（宿舍楼）、姓名、手机号、配送时间、备注
    ↓
使用优惠券/红包
    ↓
微信支付下单
    ↓
订单创建 → 推送骑手抢单
```

**AI 介入点：**
- 个性化推荐（极数·观澜 Agent）
- 优惠券自动发放（销售 Agent）

**可扩展场景（后续迭代）：**
- 果切、水果捞、果茶、水果拼盘

---

### Scene 4：配送（骑手视角）

```
骑手抢单（刷新列表 → 点击抢单 → 地图导航）
    ↓
到店取货 → 核验二维码（或核对手机号后四位）
    ↓
配送中 → 实时位置更新
    ↓
送达 → 核验收货人 → 订单完成
    ↓
异常处理：不在 → 放外卖柜 + 拍照凭证
```

**AI 介入点：**
- 配送路径优化（地图API）
- 骑手端订单信息推送（实时）

## 四、AI Agent 智能体体系

### 4.1 蜂群架构总览

```
用户请求
    ↓
[ 蜂王 Queen ]
  角色：任务分发、复杂决策、状态管理
  模型：DeepSeek-R1 / Qwen-Max（云端）
    ↓
[ 8个子智能体 ]（各自负责一个业务域）
    ↓
中央数据总线（统一数据源，消除Agent间信息碎片化）
```

### 4.2 子智能体定义

| Agent | 名称 | 核心职责 | 模型选择 |
|-------|------|---------|---------|
| 市场调研 | 墨菲（农价侦探） | 分析采购清单、预算、报价、售价 | 本地 Ollama（DeepSeek-7B） |
| 产销联络 | 阿强（产地通） | 源头谈判、供货商储备 | 本地 Ollama |
| 冷藏技术 | 智果博士 | 冷藏建议、市场波动预警 | 本地 Ollama |
| 数据分析 | 观澜（极数） | 销售数据分析、趋势预测 | 本地 Ollama |
| 自媒体运营 | 灵感（农创） | 广告投放、文案生成、社群推送 | 本地 Ollama |
| 销售转化 | 销售Agent | 流量转化、产品介绍话术 | 本地 Ollama |
| 客服售后 | 小优（智服版） | 售后答疑、投诉处理 | 云端（阿里百炼 Qwen-Long） |
| 财务会计 | 财安（零误） | 实时数据对接、财务报表生成 | 云端（DeepSeek-V3） |

### 4.3 中央数据总线（关键架构决策）

> **来自想法.md 的核心改进建议**

各 Agent 之间通过统一的**中央数据总线**通信，避免信息碎片化：

```
数据库（MySQL）←→ [ 中央数据总线 ] ←→ 各子智能体
                       ↓
              数据变更事件 → 触发相关Agent
```

**实现方式：**
- 数据库变更通过 Trigger / CDC 机制发布事件
- 各 Agent 订阅自己关注的数据变更
- 例如：采购价变更 → 自动同步到财务Agent

## 五、技术架构

### 5.1 前端：微信小程序（统一入口）

- 框架：Uniapp（一套代码，编译为小程序/H5）
- UI 组件：Vant Weapp（轻量）
- 地图：腾讯地图 SDK
- 支付：微信支付 API

### 5.2 后端：Node.js / Python FastAPI

- 角色权限中间件（JWT + 角色字段）
- RESTful API + WebSocket（实时状态）
- 文件上传（图片存储到腾讯云 COS）

### 5.3 数据库

| 库 | 技术 | 用途 |
|----|------|------|
| 主库 | MySQL（腾讯云） | 订单、用户、库存、商品 |
| 缓存 | Redis | 会话、实时状态、分布式锁 |
| 文件存储 | 腾讯云 COS | 图片、凭证照片 |

### 5.4 AI 推理层（本地优先）

```
┌─────────────────────────────────────────────┐
│              One-API（模型路由）              │
│   统一入口，转换为 OpenAI 标准协议            │
└────────────────┬────────────────────────────┘
                 │
        ┌────────┴────────┐
        ↓                 ↓
  [ 云端推理 ]        [ 本地推理 ]
  阿里百炼            Ollama（Mac M4 MLX）
  DeepSeek           deepseek-7b / qwen-2.5-7b
  （复杂推理）         （格式化/文案/分类）
```

**成本控制策略：**
1. **Context Caching**：静态知识库（冷藏指南、采购SOP）缓存，复用 Token
2. **Prompt 压缩**：`"Output JSON only. No prose."` 约束输出
3. **本地优先**：简单任务全走本地；仅蜂王复杂决策走云端

### 5.5 Swarm 编排层：Ruflo

- 定义蜂王 + 8子智能体的任务流转规则
- 使用 `transfer` 函数实现角色切换
- 部署在腾讯云 Docker（2核4G 足够）

## 七、非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 小程序页面加载 ≤ 2s，API 响应 ≤ 500ms |
| **可用性** | 核心下单路径可用性 ≥ 99.5% |
| **安全** | 用户密码 bcrypt 加密，支付走微信官方接口，身份证/手机号脱敏存储 |
| **扩展性** | 商超种类（果切/水果捞）可插件式扩展 |
| **合规** | 微信小程序账号备案，食品类目需相关资质 |

## 八、技术债务与约束

| 约束项     | 当前决策                     | 后续优化方向            |
| ------- | ------------------------ | ----------------- |
| 单人开发    | 微信小程序用 Uniapp 节省跨端工作量    | 考虑独立骑手 App（团队扩大后） |
| 微信支付资质  | 使用个人主体（有限额）              | 公司化后申请商户号         |
| AI 推理成本 | 本地为主，Token 消耗控制在 100元/月内 | 随用户量增长动态调整        |
| 数据存储    | MySQL 单库                 | 分库分表（用户量 > 1万后评估） |
