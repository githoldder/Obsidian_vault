1. 如图显示某程序的逻辑结构。试为它设计足够的测试用例，分别实现对程序的语句覆盖、判定覆盖和条件覆盖。
程序逻辑如下：
![[Pasted image 20260616102456.png]]
开始
↓
判断：(a>1) AND (b<2)
若为真，则执行 x=c+1
若为假，则跳过
↓
判断：(a==3) OR (x>3)
若为真，则执行 x=x+c
若为假，则跳过
↓
打印 a,b,c,x
↓
结束

该程序有两个判定：
D1 = (a>1) AND (b<2)
D2 = (a==3) OR (x>3)

该程序有四个条件：
C1：a>1
C2：b<2
C3：a==3
C4：x>3

![[Pasted image 20260616102348.png]]
┌────────────┬──────────────────────────────┬──────────────────────┬──────────────────────┐
│ 覆盖种类   │ 需满足的条件                  │ 测试用例              │ 预期输出              │
├────────────┼──────────────────────────────┼──────────────────────┼──────────────────────┤
│ 语句覆盖   │ D1为真，D2为真，两条赋值语句   │ a=3,b=1,c=2,x=0        │ a=3,b=1,c=2,x=5        │
│            │ x=c+1 和 x=x+c 都被执行        │                      │                      │
├────────────┼──────────────────────────────┼──────────────────────┼──────────────────────┤
│ 判定覆盖   │ D1为真，D2为真                 │ a=3,b=1,c=2,x=0        │ a=3,b=1,c=2,x=5        │

├────────────┼──────────────────────────────┼──────────────────────┼──────────────────────┤
│ 条件覆盖   │ C1真，C2真，C3真，C4假          │ a=3,b=1,c=2,x=0        │ a=3,b=1,c=2,x=5        │
│            │ C1真，C2假，C3假，C4真          │ a=2,b=3,c=2,x=4        │ a=2,b=3,c=2,x=6        │
│            │ C1假，C2真，C3假，C4假          │ a=0,b=1,c=2,x=1        │ a=0,b=1,c=2,x=1        │
└────────────┴──────────────────────────────┴──────────────────────┴──────────────────────┘

说明：

语句覆盖要求程序中的每条可执行语句至少执行一次。取 a=3,b=1,c=2,x=0 时，D1=(3>1) AND (1<2)=真，所以执行 x=c+1，得到 x=3；D2=(3==3) OR (3>3)=真，所以执行 x=x+c，得到 x=5。因此该用例可以实现语句覆盖。

判定覆盖要求每个判定的真、假结果至少各出现一次。用例 a=3,b=1,c=2,x=0 可使 D1、D2 都为真；用例 a=1,b=3,c=2,x=1 可使 D1、D2 都为假。因此这两组用例可以实现判定覆盖。

条件覆盖要求每个基本条件至少取一次真值和一次假值。用例 a=3,b=1,c=2,x=0 可覆盖 C1真、C2真、C3真、C4假；用例 a=2,b=3,c=2,x=4 可覆盖 C1真、C2假、C3假、C4真；用例 a=0,b=1,c=2,x=1 可覆盖 C1假、C2真、C3假、C4假。因此这三组用例可以实现条件覆盖。


2. 查阅 CMMI1.3 标准，描述过程和产品质量保证、风险管理这两个过程域的主要活动（实践）。

过程和产品质量保证的主要作用是客观检查项目过程和工作产品是否符合规定要求。它的主要活动包括：检查项目过程是否按照计划、标准和规程执行；检查需求文档、设计文档、代码、测试用例、测试报告等工作产品是否符合要求；记录发现的不符合项；跟踪不符合项的整改和关闭情况；向项目经理和相关人员报告质量问题。简单来说，过程和产品质量保证就是检查过程、检查产品、发现问题、跟踪整改、报告质量状态。

风险管理的主要作用是提前发现项目中可能出现的问题，并采取措施降低风险影响。它的主要活动包括：制定风险管理计划；识别项目风险；分析风险发生的可能性和影响程度；确定风险优先级；制定风险应对措施；持续跟踪和控制风险。常见风险包括需求变更风险、技术风险、人员风险、进度风险、成本风险、质量风险和环境风险。简单来说，风险管理就是识别风险、分析风险、制定措施、持续跟踪。

集成测试是把已经完成单元测试的模块按照设计要求组合起来，检查模块之间的接口、数据传递和协同工作是否正确的过程。该过程的输入包括需求和设计文档、已完成单元测试的模块、集成测试计划和用例、测试环境和测试数据。集成测试过程主要包括制定测试计划、搭建测试环境、按模块依赖顺序集成、执行接口和模块协同测试、记录并修复缺陷、进行回归测试并形成报告。该过程需要测试环境、测试管理工具、缺陷管理工具和接口测试工具等资源，由测试人员、开发人员、项目经理和质量保证人员共同参与。执行时应按照测试计划、接口文档、模块依赖关系和缺陷管理流程进行。该过程的输出是集成测试报告和通过集成测试的软件版本。评价指标包括测试用例执行率、测试通过率、缺陷发现数量和缺陷修复率。


4. 描述 ISO9001 的高阶结构与 PDCA 的关系。

ISO9001 的高阶结构主要包括第4章组织环境、第5章领导作用、第6章策划、第7章支持、第8章运行、第9章绩效评价和第10章改进。PDCA 是质量管理中的持续改进方法，其中 P 表示策划，D 表示执行，C 表示检查，A 表示改进。

ISO9001 的高阶结构与 PDCA 循环是一一对应的。第4章到第7章主要对应 P 策划阶段，组织需要理解内外部环境，明确领导责任，识别风险和机会，制定质量目标，并准备必要的资源、能力、沟通和文件。第8章对应 D 执行阶段，组织按照策划要求实施产品和服务的运行过程。第9章对应 C 检查阶段，组织通过监视、测量、内部审核和管理评审，评价质量管理体系的运行效果。第10章对应 A 改进阶段，组织处理不合格，采取纠正措施，并持续改进质量管理体系。

因此，ISO9001 提供了质量管理体系的结构框架，PDCA 提供了质量管理体系持续改进的方法。两者结合起来，可以使组织按照“策划、执行、检查、改进”的循环方式不断提高产品和服务质量。
