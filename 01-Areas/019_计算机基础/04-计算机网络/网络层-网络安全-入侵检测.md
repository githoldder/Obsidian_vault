# 入侵检测与入侵防御（IDS/IPS）

## 📖 问题-答案

### IDS 和 IPS 是什么？有什么区别？

**IDS（入侵检测系统）** 和 **IPS（入侵防御系统）** 都是网络安全监控技术，核心区别在于：

- **IDS** = 监控 + 报警。像保安巡逻发现异常后打报告，但不主动拦截
- **IPS** = 监控 + 实时阻断。像保安巡逻发现异常后当场制服

IDS 部署在**旁路模式**（复制流量来分析，不影响真实流量），IPS 部署在**串联模式**（流量必须穿过它才能到达目标）。

### IDS/IPS 核心技术：检测引擎

检测引擎是 IDS/IPS 的大脑，主要有三种方法论：

**1. 基于签名（Signature-Based）**
- 维护一个攻击模式库（类似杀毒软件的病毒库）
- 匹配已知攻击的特征：特定的网络包序列、URL 中的 SQL 注入语法、恶意 Payload 的字节模式
- Snort/Suricata 规则示例：
```
alert tcp $EXTERNAL_NET any -> $HOME_NET 80 (
  msg:"SQL Injection - SELECT UNION";
  flow:to_server,established;
  content:"union select"; nocase;
  sid:1000001;
)
```
- **优势**：误报率低，精确度高
- **劣势**：只能检测已知攻击，对零日漏洞（0-day）和变种无效

**2. 基于异常（Anomaly-Based）**
- 建立正常行为的基线模型（"这台服务器平时每小时 HTTP 请求 1000 左右"）
- 当流量偏离基线超过阈值时告警
- **优势**：可以不依赖签名发现未知攻击
- **劣势**：误报率高，基线建立困难（"异常"不一定是攻击，可能是促销活动导致流量翻倍）

**3. 基于策略（Policy-Based）**
- 管理者定义允许和不允许的行为规则（"不允许 FTP 从互联网访问内网"）
- 任何违反策略的行为触发告警
- 比签名检测更宽泛，但需要精确了解自身网络环境

**现代 IDS/IPS 通常是三者的混合体**。以签名匹配为核心（最快、最准），辅以异常检测发现未知威胁，加上策略规则兜底。

### 网络 IDS vs 主机 IDS

**NIDS（网络入侵检测系统）**
- 部署在网络关键节点（交换机镜像端口/TAP 分流器）
- 分析镜像到的所有流量，覆盖整个网段
- 优势：集中部署，一台设备保护一个子网
- 劣势：无法看见加密流量内容，在高速网络（>40 Gbps）中分析难度大

**HIDS（主机入侵检测系统）**
- 部署在受保护的主机上（如 OSSEC、Wazuh、Tripwire）
- 监控：文件完整性（重要配置文件被改了？）、日志分析（/var/log/auth.log 有多次失败登录？）、进程行为（未知进程突然启动？）、rootkit 检测
- 优势：可以看到解密后的内容 + 主机内部状态
- 劣势：每台主机都要部署和维护，攻击者获得 root 后可以禁用 HIDS

最佳的部署策略：**NIDS + HIDS 互补**。NIDS 看网络"外部视角"，HIDS 看主机"内部视角"。

### 现实中的 IDS/IPS 工具

**Snort**
- 经典的开源 NIDS/IPS，由 Cisco 维护
- 基于签名的规则匹配引擎
- 规则语言简单强大，社区规则库丰富
- VRT（漏洞研究团队）提供付费的订阅规则（更新最快）

**Suricata**
- 新兴的开源替代品，性能优于 Snort
- **多线程架构**（Snort 单线程是主要瓶颈）
- 支持硬件加速、GPU 卸载
- 内置文件提取和 Lua 脚本扩展

**Zeek（原 Bro）**
- 不完全是传统 IDS——它是**网络安全监控（NSM）平台**
- 不对流量做"攻击/正常"的二进制判断，而是**记录一切**：看到什么连接、用了什么协议、传了什么文件
- 分析人员用 Zeek 脚本语言对数据进行后处理，挖掘异常模式
- 更偏"安全取证"而非"实时阻断"

### IDS/IPS 部署位置策略

```
Internet → [边界防火墙] → [外部IPS] → [DMZ 交换机] → [内部防火墙] → [内部IPS] → [内部交换机]
```

- **外部 IPS**：阻挡已知的攻击流量（端口扫描、漏洞利用尝试）
- **内部 IPS**：检测已穿透边界的攻击（钓鱼邮件的 C2 回连、数据外泄）
- **DMZ 区域**：既被外部 IPS 保护，内部也通过额外层隔离

### 为什么 IDS/IPS 都需要持续调优？

新部署的 IDS 几乎必然是"**告警海啸**"——每天数十万甚至上百万条告警。其中 99% 是：
- 误报（false positive）：IPS 挡住了正常业务流量，可能造成生产事故
- 低危噪音（扫描器不是攻击，只是探测）
- 已修补漏洞的告警（这个漏洞早就打了补丁了）

**调优（Tuning）** 是 IDS/IPS 的头等大事：禁用无意义规则、设置阈值、创建例外、按资产重要性分级告警。未经调优的 IDS = 不会有人看的噪声源。

### IDS/IPS 与 AI/ML

近年来的趋势：
- 机器学习模型用于缩小异常检测的误报范围（从每天 10 万条降到 100 条）
- 用户与实体行为分析（UEBA）：不是看单次请求，而是看用户/设备的长期行为模式
- NDR（网络检测与响应）：不是单纯告警，而是基于检测结果自动触发响应动作（隔离主机、阻断 IP、捕获 PCAP 取证）
