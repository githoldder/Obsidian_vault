# 文档审核清单

## 使用说明

本文档用于AI辅助文档审核。在文档完成后，按照以下清单逐项检查，确保文档质量。

---

## 1. 基础信息检查

### 1.1 文档元信息

- [ ] **文档标题**: 清晰、准确反映内容
- [ ] **版本号**: 符合v{主版本}.{次版本}格式
- [ ] **更新日期**: 格式为YYYY-MM-DD
- [ ] **文档状态**: 明确标注（草稿/审核中/已发布）

### 1.2 变更记录

- [ ] 变更记录表格存在
- [ ] 最新变更已记录
- [ ] 变更描述清晰具体

---

## 2. 结构完整性检查

### 2.1 必需章节

根据文档类型检查必需章节：

**PRD文档必需章节**:
- [ ] 概述（背景、目标、范围）
- [ ] 需求分析
- [ ] 功能设计
- [ ] 交互设计
- [ ] 验收标准

**分析文档必需章节**:
- [ ] 分析背景
- [ ] 数据说明
- [ ] 核心发现
- [ ] 结论与建议

**需求文档必需章节**:
- [ ] 业务背景
- [ ] 用户画像
- [ ] 功能需求
- [ ] 非功能需求

### 2.2 层级结构

- [ ] 一级标题只有文档标题
- [ ] 层级没有跳跃（如二级下直接四级）
- [ ] 同级标题逻辑一致

---

## 3. 内容质量检查

### 3.1 需求描述

- [ ] 用户故事符合"作为...我想要...以便..."格式
- [ ] 需求描述清晰、无歧义
- [ ] 功能范围明确（包含/不包含）

### 3.2 验收标准

- [ ] 所有标准可量化
- [ ] 包含正向测试场景
- [ ] 包含负向测试场景
- [ ] 包含边界条件

### 3.3 术语一致性

- [ ] 术语表存在且完整
- [ ] 全文术语使用统一
- [ ] 首次出现术语有定义

---

## 4. 格式规范检查

### 4.1 表格

- [ ] 表格有表头
- [ ] 表头使用中文
- [ ] 数据对齐正确
- [ ] 复杂表格有说明

### 4.2 图表

- [ ] 流程图使用Mermaid语法
- [ ] 图表有标题
- [ ] 图表逻辑正确
- [ ] ER图标注主外键

### 4.3 链接

- [ ] 内部链接使用Wiki格式
- [ ] 链接指向正确
- [ ] 无死链

### 4.4 代码

- [ ] 代码块指定语言
- [ ] 代码格式正确
- [ ] 关键代码有注释

---

## 5. 逻辑一致性检查

### 5.1 数据一致性

- [ ] 数据前后一致
- [ ] 数字计算正确
- [ ] 版本号递增正确

### 5.2 逻辑一致性

- [ ] 业务流程逻辑通顺
- [ ] 状态转换完整
- [ ] 异常处理覆盖全面

---

## 6. MVP原则检查

### 6.1 范围控制

- [ ] 功能范围符合MVP原则
- [ ] 无过度设计
- [ ] 不包含二期功能

### 6.2 优先级

- [ ] 功能有明确优先级（P0/P1/P2）
- [ ] P0功能确实是核心功能
- [ ] 可延后功能已标注

---

## 7. 可行性检查

### 7.1 技术可行性

- [ ] 技术方案有依据
- [ ] 没有无法实现的需求
- [ ] 依赖项已明确

### 7.2 资源可行性

- [ ] 开发周期合理
- [ ] 人力需求明确
- [ ] 外部依赖可控

---

## 8. 安全与合规

### 8.1 数据安全

- [ ] 敏感数据处理有说明
- [ ] 隐私保护措施到位
- [ ] 数据存储符合规范

### 8.2 合规性

- [ ] 符合相关法规
- [ ] 用户协议相关功能已考虑

---

## 附录: 常见问题

### Q1: 如何处理审核意见冲突？

1. 记录各方意见
2. 标注风险和建议
3. 由产品负责人最终决策
4. 决策结果记录在文档中

### Q2: 紧急情况下可以跳过审核吗？

紧急情况下可以：
1. 先发布临时版本
2. 标注"紧急发布，未经完整审核"
3. 24小时内补充完整审核

### Q3: 审核不通过的文档如何处理？

1. 移动到drafts/目录
2. 根据审核意见修改
3. 重新提交审核
4. 审核通过后移动到prds/目录
