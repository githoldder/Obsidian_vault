## 项目说明
***
项目名称：苍穹外卖 (Sky Takeaway) - 数字化餐饮管理系统
项目愿景：打造餐饮企业一站式全生命周期管理平台，实现从下单到交付的最小闭环。
***

1. 需求背景与痛点 (Core Pain Points)
--------------------------------------------------------------------------------
- 运营端效率低下：传统餐饮依赖人工对菜品、套餐、订单进行管理，数据滞后，容错率低。
- 客户端体验单薄：用户缺乏直观的选餐、支付、订单追踪及地址管理界面，交互体验不连贯。
- 数据分析缺失：经营者无法通过数字化手段实时观测营业额、用户画像及销量排行。

2. 核心功能与最小闭环 (Minimum Viable Product - MVP)
--------------------------------------------------------------------------------
项目分为“管理端 (Admin)”与“用户端 (User)”两大闭环：
- 基础管理闭环：员工登录 -> 菜品/分类管理 -> 菜品上架。
- 核心交易闭环：用户微信登录 -> 选餐下单 -> 微信支付 -> 商家接单 -> 状态更新。
- 经营分析闭环：营业额报表 -> 销量排名 Top10 -> 订单统计看板。

3. 技术栈定义 (Tech Stack)
--------------------------------------------------------------------------------
- 后端核心：Java 8/11 + Spring Boot 2.7.3 (快速构建、开箱即用)
- 持久层：MyBatis Plus (简化 CRUD) + Redis (缓存菜品、购物车、Token)
- 接口管理：Swagger/Knife4j (自动化接口文档，供前后端对接)
- 数据库：MySQL 8.0 (持久化存储)
- 前端交互：Vue.js / ElementUI (管理端) + 微信小程序 (用户端)
- 特色中间件：HttpClient (坐标解析)、Spring Task (定时任务处理过期订单)、WebSocket (商家端语音播报)

4. 流水线定义 (Pipeline & Workflow)
---
- 架构分层：controller (接入层) -> service (逻辑层) -> mapper (持久层) -> POJO (实体类)。
- 异常管理：全局异常处理器 (GlobalExceptionHandler)，统一返回结果 (Result<>)。
- 开发顺序：数据库建模 -> 基础接口实现 -> Redis 缓存优化 -> 业务逻辑迭代 -> 联调测试。

5. 关键业务约束与 KPI (Business Rules & KPI)
***
- 安全约束：所有受限接口必须经过 JWT 拦截器校验，实现员工与用户权限隔离。
- 数据一致性：菜单与分类删除必须包含关联检查（如分类下有菜品则禁止删除）。
- 成功标准：10天内实现从零部署、数据库初始化、核心增删改查接口通过 Postman 自动化测试，并完成答辩演示。
