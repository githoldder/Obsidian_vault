## 一、开发原则

### 1.1 核心铁律

| 原则 | 说明 |
|------|------|
| **MVP优先** | 第一版只做"背词+闹钟+看板"三件事，其余全部砍掉 |
| **深度优于广度** | 每个功能做到极致，不做功能堆砌 |
| **离线优先** | 核心功能（背词/提醒/看板）必须100%离线可用 |
| **极致省钱** | AI/RAG调用严控成本，本地优先，云端兜底 |
| **数据不丢失** | 用户学习数据本地持久化，任何崩溃不丢失进度 |

### 1.2 执行顺序（雷打不动）

```
需求分析 → 概要设计 → 详细设计 → 任务列表拆解 → 逐条执行 → 测试验收
```

**严禁**：边写代码边想需求 / 未设计就开始开发 / 测试前上线

### 1.3 代码与文档标准

- 优先输出 **Markdown** 文档、**Mermaid** 图表
- 代码必须**模块化**，单文件不超过300行
- 每个函数必须有注释说明**输入/输出/副作用**
- 数据库变更必须写 **Migration 脚本**，不允许手动改库

## 二、技术选型

### 2.1 移动端

| 技术 | 选型 | 理由 |
|------|------|------|
| 跨平台框架 | **Flutter** | iOS/Android一套代码，性能接近原生 |
| 本地数据库 | **SQLite（via sqflite）** | 轻量、离线、速度快 |
| 状态管理 | **Riverpod** | 简洁、可测试性强 |
| 本地通知/闹钟 | **flutter_local_notifications + android_alarm_manager** | 系统级闹钟，不依赖App存活 |
| Markdown解析 | **flutter_markdown** | 语法3.0库的渲染 |
| 图表 | **fl_chart** | 数据看板折线图/柱状图 |

### 2.2 后端（最小化）

| 技术 | 选型 | 理由 |
|------|------|------|
| 后端框架 | **FastAPI (Python)** | 轻量，RAG集成友好 |
| RAG框架 | **LlamaIndex / LangChain** | 本地知识库检索 |
| 向量数据库 | **ChromaDB（本地）** | 免费、轻量、离线可用 |
| LLM | **本地模型（Ollama）/ OpenAI API兜底** | 优先本地，控成本 |
| 部署 | **Docker + 轻量云服务器** | 一期用最小实例 |

### 2.3 内容数据格式

- 95篇文章：**JSON格式**存储（article_id, title, year, type, content, sentences[]）
- 语法3.0：**Markdown → 解析为结构化JSON** → 导入数据库
- 单词表：**CSV导入** → SQLite word表

### Step 9：数据看板统计

```sql
-- 本周单词进度
SELECT COUNT(*) FROM user_word
WHERE user_id=? AND learned_at >= date('now', '-7 days');

-- 单词掌握率
SELECT
  SUM(CASE WHEN mastered=1 THEN 1 ELSE 0 END) * 100.0 / COUNT(*) as mastery_rate
FROM user_word WHERE user_id=?;

-- 本周复习完成率
SELECT
  SUM(completed) * 100.0 / COUNT(*) as completion_rate
FROM review_session
WHERE user_id=? AND session_date >= date('now', '-7 days');
```

**看板更新时机**：每次完成复习任务后立即刷新（非定时轮询）

**验收标准**：
- [ ] 四大维度（单词/复习/阅读/语法）进度%实时准确
- [ ] 趋势图过去7天数据正确
- [ ] 激励文案根据进度动态生成
- [ ] 看板打开响应时间 < 500ms
