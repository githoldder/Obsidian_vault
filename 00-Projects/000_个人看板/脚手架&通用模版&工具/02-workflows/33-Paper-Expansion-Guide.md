# 论文内容扩写与 AI 辅助指南

> 基于高质量信息输入的内容扩写方法论，解决「AI 味重」「逻辑空洞」「信息堆砌」三大痛点
> **更新（2026-05）**：结构调整为「扩写方法 → 降重方法（可选后处理）」

---

## 核心工作流

```
第一步：用 AI 扩写高质量论文（逻辑严密、工整规范）
         ↓
第二步：输出结构化 LaTeX patch，而不是 Markdown 自由正文
         ↓
第三步：执行 LaTeX 语法审查 + 论文审稿人审查
         ↓
第四步：注入 .tex 并编译回归
         ↓
第五步（如有 AIGC 查重要求）：用降重提示词/方法进行后处理
         ↓
第六步：提交检测
```

> **重要原则**：扩写阶段专注论文质量，降重是**可选的后处理**，不是扩写的前置目标。
> 逻辑严密、工整规范的论文天然会有较高的 AI 特征，这是正常的。
> 只有在**教育局/学校有硬性 AIGC 率指标**时，才需要降重处理。
> 如果扩写结果要进入 `.tex`，必须走 [[36-LaTeX-Injection-Review-Skill]]，禁止直接复制 Markdown 正文。

---

## 0. LaTeX 注入硬规则

当目标是写入 LaTeX 论文项目时，以下规则优先级最高：

1. AI 不直接输出 Markdown 正文作为最终产物。
2. AI 必须输出结构化 LaTeX patch 或注入脚本。
3. patch 必须包含 `target_file`、`operation`、`anchor`、`latex`、`assumptions`、`review_required`。
4. patch 注入前必须通过 LaTeX 语法审查和论文审稿人审查。
5. 注入后必须编译，至少完成 smoke test。
6. 如果输出含有 Markdown 标题、Markdown 列表、`**加粗**`、代码围栏包裹论文正文，视为无效输出。

## 一、扩写工作流（核心方法论）

### Step 1: 补充输入（必做！）

**原则**：扩写前必须确保有**足够的高质量原材料**，否则 AI 只能炒冷饭。

#### 信息补充 SOP

1. **明确扩写目标**
   - 要扩写哪个段落？
   - 缺少什么信息？（数据？案例？对比？）

2. **按场景补充信息**
   - 📊 **调研报告** → 参考 [[32-Industry-Research-SOP]]
   - 📚 **学术论文** → 检索高质量文献（见 [[31-Paper-Info-Processing]]）
   - 💡 **产品分析** → 补充竞品数据、用户反馈

3. **结构化输入格式**

```markdown
## 扩写任务

### 目标段落
[原文]

### 缺少的信息
1. 缺少 XX 数据支撑
2. 缺少 XX 案例对比

### 已收集的补充材料
- [材料1]：...
- [材料2]：...
```

### Step 2: 生成扩写（提示词模板）

#### 模板 A：学术论文扩写

```
请基于以下材料，扩写以下段落，并输出结构化 LaTeX patch。要求：
1. 保持学术严谨性，避免车轱辘话
2. 每个论点必须有论据支撑
3. 使用金字塔原理结构：背景 → 问题 → 分析 → 结论
4. 禁止车轱辘话来回说
5. 适当使用连词体现逻辑链（因为...所以...，然而...，此外...）
6. 禁止输出 Markdown 正文
7. 禁止 Markdown 标题、Markdown 列表、**加粗** 和代码围栏包裹论文正文
8. 输出必须是 JSON patch，字段包括 target_file、operation、anchor、latex、assumptions、review_required
9. latex 字段必须是合法 LaTeX 正文，特殊字符如 %、&、_ 必须按 LaTeX 规则转义
10. 不得编造 cite key，只能使用输入中给定的 cite key

## 原文
[待扩写段落]

## 补充材料
[Step 1 收集的材料]

## 风格要求
- 正式书面语
- 保留原文核心观点，只扩展论证深度
- 允许使用复杂句式，但必须有信息增量

## Patch 目标
target_file: [chapters/xx.tex]
operation: [insert_after / replace_block / append_to_section]
anchor: [LaTeX 锚点]
```

#### 模板 B：调研报告扩写

```
请将以下要点扩展为完整段落，并输出结构化 LaTeX patch。要求：
1. 结论先行，每个段落首句必须是核心观点
2. 数据必须有来源标注
3. 使用「总-分-总」结构
4. 避免「由于...因此...」这种无脑因果
5. 禁止输出 Markdown 正文，必须输出 JSON patch
6. latex 字段必须通过 [[37-LaTeX-Injection-Review-Skill]] 的双重审查

## 要点
[待扩写要点]

## 补充材料
[材料]

## Patch 目标
target_file: [chapters/xx.tex]
operation: [insert_after / replace_block / append_to_section]
anchor: [LaTeX 锚点]
```

#### 模板 C：商业文案扩写

```
请将以下卖点扩写为有说服力的文案。要求：
1. 场景化：代入用户使用场景
2. 数字化：用具体数字代替「很多」「不错」
3. 差异化：对比竞品/传统方案
4. 人话：像真人写的

## 卖点
[待扩写内容]
```

## 二、痛点专项解决

### 问题 1：AI 味太重

**原因**：提示词缺少风格约束，AI 默认输出「正确的废话」

**解决**：添加风格锚定

```
风格锚定（必加）：
- 禁止使用「首先」「其次」「最后」序列词（除非真正列举步骤）
- 禁止使用「综上所述」「可以看出」「显而易见」等套话
- 允许使用短句增强节奏
- 使用具体案例代替抽象论述
- 适当使用口语化表达（如「说白了」「本质上」「某种程度上」）
```

### 问题 2：逻辑空洞

**原因**：输入信息不够，AI 只能炒冷饭

**解决**：分步扩写

```
Step 1: 先让 AI 列出「可以从哪些角度展开」
Step 2: 逐个角度补充材料
Step 3: 再进行扩写
```

### 问题 3：信息稀释

**原因**：只扩不补，原有信息被稀释

**解决**：保持信息密度

```
扩写原则：
- 每扩写 100 字，必须新增至少 1 个信息点
- 不能只是换说法，要加新内容
- 新增内容必须是「补充」而非「重复」
```

## 三、扩写质量检查清单

- [ ] **信息增量**：新增内容是否带来新信息？
- [ ] **逻辑连贯**：段落之间是否有明确的逻辑链？
- [ ] **风格自然**：是否像人写的，而非 AI 堆砌？
- [ ] **信息密度**：是否在有效篇幅内最大化信息量？
- [ ] **来源标注**：数据/引用是否有来源？
- [ ] **LaTeX patch**：如果进入 `.tex`，是否输出结构化 patch 而非 Markdown？
- [ ] **语法审查**：是否通过 LaTeX 语法审查？
- [ ] **审稿审查**：是否通过论文审稿人审查？
- [ ] **编译回归**：注入后是否完成编译 smoke test？

## 四、场景化提示词库

### 场景 1：文献综述扩写

```
请为以下研究主题撰写文献综述。要求：
1. 按「流派/方法」分组，而非按文献罗列
2. 每组先总结共性，再点评差异
3. 指出当前研究空白，引出你的工作

主题：[主题]
已读文献：
- [文献1]：核心观点...
- [文献2]：核心观点...
- [文献3]：核心观点...

结构要求：
- 研究现状
- 流派划分
- 不足与空白
- 本文切入点
```

### 场景 2：方法介绍扩写

```
请扩写以下技术/方法介绍。要求：
1. 背景（为什么需要）- 原理（怎么做的）- 应用（能做什么）
2. 使用流程图/伪代码说明原理
3. 对比类似方法，突出差异化优势

方法名：[方法]
核心原理：[一句话]
对比方法：[类似方法]

输出结构：
1. 背景与动机
2. 核心原理
3. 实现流程
4. 优势与局限
5. 应用场景
```

### 场景 3：数据分析扩写

```
请分析以下数据，撰写分析段落。要求：
1. 描述数据趋势
2. 解释背后原因
3. 推断未来走向
4. 用具体数字而非「增长」「下降」

数据：
[数据1]: 数值 + 变化
[数据2]: 数值 + 变化
[数据3]: 数值 + 变化

输出要求：
- 每个数据点必须有解读
- 数据之间必须有联系
- 结论必须有数据支撑
```

## 五、为什么好的论文 AIGC 率天然偏高

```
AI 扩写追求：逻辑严谨、结构规范、表达正式、术语统一
AIGC 检测逻辑：恰好识别这种「过度规整」的统计特征

结论：逻辑严密、工整规范的论文，AI 特征统计值自然偏高。
这是论文质量的副产品，不应该反过来指导写作。
```

**所以正确的做法是**：
1. 先写好论文（扩写阶段专注质量）
2. 如果有 AIGC 率硬性指标 → 再用降重方法处理
3. 如果没有 → 直接提交

### 各平台检测原理（知己知彼）

| 指标 | 检测逻辑 | 人类写作特征 |
|------|---------|------------|
| **Perplexity**（困惑度） | 文本在语言模型中的「意外程度」，AI 文本偏低 | 用词有一定不可预测性 |
| **Burstiness**（突发度） | 句子长度的变化幅度，AI 文本高度一致 | 句子长短参差不齐 |
| **词分布** | AI 文本词分布过于均匀 | 有个人写作风格偏好 |

## 七、AIGC 降重方法库

> **重要**：以下方法会改变文章的表达方式，使用前请确认：
> 「是否有 AIGC 率的硬性要求？」
> 如果没有，跳过本节，直接提交论文。

### 方法 1：句子结构破坏法（最有效）

**原理**：AIGC 检测依赖句子长度和结构的一致性统计，人为制造差异

```
❌ 原AI句（检测高危）：
"随着人工智能技术的快速发展，深度学习算法在图像识别领域取得了显著的突破，
大幅提升了识别准确率，推动了相关产业的智能化升级。"

✅ 改造后：
"AI 火了之后，深度学习在图像识别这块确实猛。
拿人脸识别来说，现在算法精度普遍达到 99% 以上，
工厂用它做质检，速度比人快，还不会累。"
```

**操作要点**：
- 短句控制在 8~15 字
- 长句控制在 60~120 字
- 每 100 字中至少插入 1 个感叹句或反问句

---

### 方法 2：词汇替换法

**原理**：AI 高频使用的词汇会触发检测阈值

| 高危 AI 词汇 | 替换方案 |
|-------------|---------|
| "首先" | "头一件"、"开头的时候" |
| "其次" | "再一个"、"紧跟着" |
| "最后" | "收尾来说"、"总之" |
| "因此" | "这也就意味着"、"说到底" |
| "所以" | "于是就"、"这直接导致" |
| "不难发现" | "说白了"、"说实在的" |
| "显而易见" | "明摆着"、"有目共睹" |
| "显著提升" | "涨了不少"、"跑出了漂亮曲线" |
| "持续稳定" | "一直在跑"、"基本没掉过链子" |
| "不断优化" | "一直在调"、"迭代了 N 轮" |
| "广泛应用" | "到处都在用"、"装机量很可观" |
| "综上所述" | "说了一圈"、"绕回来讲" |

---

### 方法 3：人称注入法（强烈推荐）

**原理**：AIGC 几乎不主动使用第一人称体验性表达

```
❌ AI 标准句式：
"该方法在实验中取得了良好的效果，验证了算法的有效性。"

✅ 加人称后：
"我们在三个数据集上跑了这套方法，说实话，结果比我们预期的好。
尤其是中文语料那块，准确率直接上了一个台阶。
当然，中间也有踩坑——比如数据预处理没做好，那批结果就很难看。"
```

**可用句式**：
- "坦白说"、"实话说"、"说实在的"
- "我测试发现"、"我们跑了几轮"
- "踩过这个坑"、"绕了不少弯路"
- "有意思的是"、"没想到的是"

---

### 方法 4：逻辑跳跃法（高阶）

**原理**：人类写作会有「想到哪写到哪」的特征，AI 不会

```
❌ AI 规整写法：
"第一，技术准备充分。第二，资金到位。第三，团队稳定。"

✅ 逻辑跳跃写法：
"技术这块基本 OK 了——当然还有些边角问题没处理完。
钱的事，上周刚跟投资人聊过，有戏。
倒是团队，最近有人想跳槽，这个得盯紧。"
```

---

### 方法 5：专业术语本土化（学术专用）

**原理**：AI 习惯使用标准翻译术语，增加本地化表达可降低检测

```
❌ AI 术语表达：
"该研究采用卷积神经网络进行图像特征提取，通过交叉熵损失函数进行模型优化。"

✅ 本土化表达：
"图像特征这块，我们用的是 CNN 来提取。
Loss 函数选的交叉熵，训练下来效果还行。"
```

## 八、AIGC 降重提示词模板

### 模板 D：AI 文本降重专用（不改原意）

> 使用场景：扩写完成后，如有 AIGC 率要求，执行此模板

```
请对以下段落进行 AIGC 降重处理，要求：
1. 不改变原意，不删减核心信息
2. 句子长度必须有明显波动（短句 <15字 与 长句 >50字 交替）
3. 将高频 AI 词汇替换为更口语化/个性化的表达
4. 每 80~120 字插入 1 个感叹句或反问句
5. 加入 1~2 处轻微逻辑跳跃（模拟人类思维特征）
6. 保留学术论文的专业性，不能变成大白话

## 原文
[待降重段落]

## 输出
直接输出降重后的文本，不要解释
```

### 模板 E：初稿 → AIGC 安全版（完整流程）

```
请对以下学术论文初稿进行 AIGC 安全化处理，输出可直接提交检测的版本。

## 处理流程
1. 识别所有高危 AI 句式并标记
2. 对每个高危句执行「结构破坏」（拆解长句、合并短句、制造长度差）
3. 替换高频 AI 词汇
4. 注入人称和主观体验表达
5. 检查整体 AIGC 概率（以维普标准 <15% 为目标）

## 初稿内容
[粘贴初稿]

## 注意事项
- 核心学术观点和论据必须完整保留
- 数据和方法描述保持准确性
- 不得改变技术路线的原意
- 输出全文，不做摘要
```

---

## 九、降重后自检清单

- [ ] 句子长度是否有明显长短交替？
- [ ] 同一词汇是否连续出现 ≤3 次？
- [ ] 是否至少有 3 处以上第一人称/主观表达？
- [ ] 是否有感叹句、反问句混合其中？
- [ ] **维普查重预检**：在正式提交前，用维普/知网 AIGC 自检一次
