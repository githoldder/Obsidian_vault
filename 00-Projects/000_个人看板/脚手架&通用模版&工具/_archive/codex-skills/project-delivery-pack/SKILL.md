# Project Delivery Pack

Use this skill to turn product intent into a complete, reviewable, and deliverable project system.

Core principle:

```text
Human owns intent. AI owns execution.
Markdown expresses knowledge. JSON defines protocol.
Compile bridges decision and execution.
```

## Workflow

1. Identify the current plane:
   - Decision: Vision, Roadmap, Epic, Sprint, User Story, Feature, Acceptance Criteria.
   - Knowledge: PRD.md, SRS, architecture, API, database, project docs.
   - Protocol: Task.json, Sprint.json, State.json.
   - Execution: implementation, review, QA, deploy, feedback.
2. Keep human product truth in Markdown.
3. Compile executable work into JSON work units before assigning agents.
4. Produce the smallest sufficient document package for the audience: teacher, interviewer, client, team, or user.
5. Map software engineering docs to the lifecycle: requirement, architecture, detailed design, build, test, deploy.
6. Keep QA independent from builders; QA reports defects and risk.
7. Package final outputs for GitHub portfolio, client handoff, or course delivery.

## Output Contract

For project planning, return:

- decision hierarchy;
- document package scope;
- task/protocol structure when execution is needed;
- quality gates.

For documentation delivery, return:

- file list;
- document outlines or completed docs;
- consistency checks across product, engineering, and management layers.
