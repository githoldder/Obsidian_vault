### 1.2 部署策略

| 阶段  | 部署内容           | 技术方案                           |
| --- | -------------- | ------------------------------ |
| MVP | 核心功能（背词+阅读+看板） | Vercel + Supabase 免费档          |

### 1.3 Vercel 部署流程

**准备工作**：

```bash
# 1. 确保项目结构正确
kaoyan-english-app/
├── src/               # 源代码
├── index.html         # 入口文件
├── package.json       # 依赖配置
├── vite.config.ts     # Vite 配置
└── vercel.json        # Vercel 配置

# 2. 安装 Vercel CLI
npm i -g vercel

# 3. 登录 Vercel
vercel login
```

**部署步骤**：

```bash
# 方式1: 命令行部署
vercel --prod

# 方式2: GitHub 自动部署
# 1. 在 Vercel Dashboard 导入 GitHub 仓库
# 2. 配置环境变量
# 3. 每次 push 到 main 分支自动部署
```

**vercel.json 完整配置**：

```json
{
  "version": 2,
  "name": "kaoyan-english-app",
  "builds": [
    {
      "src": "package.json",
      "use": "@vercel/static-build",
      "config": { "distDir": "dist" }
    }
  ],
  "routes": [
    { "handle": "filesystem" },
    { "src": "/(.*)", "dest": "/index.html" }
  ],
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "X-XSS-Protection", "value": "1; mode=block" }
      ]
    }
  ],
  "env": {
    "VITE_SUPABASE_URL": "@supabase-url",
    "VITE_SUPABASE_ANON_KEY": "@supabase-anon-key",
    "VITE_GEMINI_API_KEY": "@gemini-api-key"
  }
}
```

### 1.4 Supabase 配置

**数据库初始化**：

```bash
# 1. 安装 Supabase CLI
npm i -g supabase

# 2. 登录
supabase login

# 3. 初始化项目
supabase init

# 4. 推送 schema 到云端
supabase db push

# 5. 生成 TypeScript 类型
supabase gen types typescript --project-id your-project-id > src/types/supabase.ts
```

**环境变量配置 (Vercel Dashboard)**：

| 变量名 | 获取位置 | 说明 |
|--------|----------|------|
| `VITE_SUPABASE_URL` | Supabase Project Settings > API | 项目 URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase Project Settings > API | 公开访问密钥 |
| `VITE_GEMINI_API_KEY` | Google AI Studio | Gemini API 密钥 |

### 1.5 GitHub 集成配置

**GitHub Actions 工作流 (.github/workflows/deploy.yml)**：

```yaml
name: Deploy to Vercel

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

      - name: Build
        run: npm run build
        env:
          VITE_SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          VITE_SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}
          VITE_GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}

      - name: Deploy to Vercel
        uses: vercel/action-deploy@v1
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
```

### 2.4 测试用例示例

**单元测试 (src/pages/__tests__/VocabCard.test.tsx)**：

```typescript
import { describe, it, expect, vi } from 'vitest'
import { render, screen, fireEvent } from '@testing-library/react'
import { VocabCard } from '../VocabCard'

describe('VocabCard', () => {
  const mockWord = {
    id: 1,
    word: 'commitment',
    meaning_zh: 'n. 承诺，保证',
    phonetic_us: '/kəˈmɪtmənt/',
  }

  it('renders word information correctly', () => {
    render(<VocabCard word={mockWord} mode="english_to_chinese" />)
    expect(screen.getByText('commitment')).toBeInTheDocument()
    expect(screen.getByText('/kəˈmɪtmənt/')).toBeInTheDocument()
  })

  it('handles correct answer', () => {
    const onAnswer = vi.fn()
    render(<VocabCard word={mockWord} mode="english_to_chinese" onAnswer={onAnswer} />)
    fireEvent.click(screen.getByText('认识'))
    expect(onAnswer).toHaveBeenCalledWith({ correct: true })
  })
})
```

**E2E 测试 (e2e/review-flow.spec.ts)**：

```typescript
import { test, expect } from '@playwright/test'

test('complete daily review flow', async ({ page }) => {
```

### 3.4 数据备份策略

**Supabase 自动备份**：

```bash
# 1. 使用 Supabase CLI 导出数据
supabase db dump -f backup.sql

# 2. 或使用 pg_dump 直接导出
pg_dump \
  --host=db.xxx.supabase.co \
  --port=5432 \
  --username=postgres \
  --dbname=postgres \
  --file=backup_$(date +%Y%m%d).sql
```

**备份频率**：

| 数据类型 | 备份方式 | 频率 |
|----------|----------|------|
| 数据库 | 自动快照 | 每日 |
| 数据库 | 手动导出 | 每周 |
| 用户上传文件 | Storage 自动备份 | 实时 |

### 3.5 问题分级与响应

| 级别 | 定义 | 响应时间 | 解决时间 | 通知方式 |
|------|------|----------|----------|----------|
| P0 | 服务完全不可用 | 15分钟 | 2小时 | 电话 + Slack |
| P1 | 核心功能受影响 | 1小时 | 4小时 | Slack |
| P2 | 次要功能问题 | 4小时 | 24小时 | 邮件 |
| P3 | 优化建议 | 24小时 | 排期处理 | GitHub Issue |

**常见故障处理**：

| 故障现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 页面白屏 | 构建失败/JS 错误 | 检查 Vercel 部署日志 |
| API 404 | Supabase API 变更 | 检查接口版本 |
| 登录失败 | Auth 配置错误 | 检查 Supabase Auth 设置 |
| AI 响应慢 | Gemini API 限流 | 检查 API 配额 + 缓存 |

### 3.6 回滚预案

```bash
# 方式1: 通过 CLI

# 方式2: 在 Dashboard 中
# 1. 进入 Project > Deployments
# 2. 找到上一个稳定版本
# 3. 点击 "Promote to Production"
```

**数据库回滚**：

```bash
# 使用 Supabase 备份恢复
supabase db restore --from backup.sql
```
