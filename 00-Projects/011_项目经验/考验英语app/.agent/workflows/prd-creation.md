# PRD创建工作流

> **工作流ID**: prd-creation-v1
> **触发条件**: 需求分析完成后
> **预计耗时**: 2-4小时

---

## 工作流概述

本工作流指导AI完成从需求文档到完整PRD的创建过程。

### 输入
- 需求文档 (BRD/MRD/UCD)
- 功能范围定义
- 用户故事

### 输出
- PRD文档
- 数据库设计
- 接口设计

---

## 执行步骤

### Step 1: PRD结构设计 (15分钟)

**任务**: 设计PRD的章节结构

**输入**:
- 产品类型
- 功能列表
- 模板文件 `templates/prd-template.md`

**输出**:
- PRD大纲 `drafts/prd-outline.md`

**提示词**:
```
基于以下功能列表，设计PRD文档结构：
{功能列表}

要求：
1. 参考 templates/prd-template.md 的章节安排
2. 根据功能复杂度调整章节深度
3. 确定每个章节的主要内容
4. 输出章节大纲和每节的要点

输出格式：
## PRD大纲

### 1. 概述
- 要点1
- 要点2
...
```

---

### Step 2: 模块拆解 (30分钟)

**任务**: 将功能拆解为详细模块

**输入**:
- PRD大纲
- 功能范围定义

**输出**:
- 模块规格 `drafts/module-specs.md`

**提示词**:
```
将以下功能拆解为详细模块：
{功能描述}

每个模块需包含：
1. 模块名称和一句话描述
2. 包含的子功能列表
3. 输入/输出定义
4. 依赖关系
5. 优先级（P0/P1/P2）

约束：
- 符合MVP原则，第一期只保留P0功能
- 模块间职责清晰，不重复
- 每个子功能可独立验收
```

---

### Step 3: 业务流程设计 (30分钟)

**任务**: 设计业务流程和页面流转

**输入**:
- 模块规格
- 用户场景

**输出**:
- 业务流程图
- 页面流转图
- `drafts/interaction-flow.md`

**提示词**:
```
为以下模块设计业务流程：
{模块名称}

输出：
1. 主业务流程（Mermaid流程图）
2. 关键分支流程
3. 异常处理流程
4. 页面流转图（状态图）

要求：
- 覆盖所有用户场景
- 明确每个步骤的输入输出
- 标注关键决策点
```

---

### Step 4: 交互设计 (45分钟)

**任务**: 详细设计用户交互

**输入**:
- 页面流转图
- 用户场景

**输出**:
- 界面原型描述
- 交互规则表
- `drafts/interaction-details.md`

**提示词**:
```
设计【{页面名称}】的详细交互：

需包含：
1. 界面布局描述（ASCII或文字）
2. 所有可交互元素说明
3. 操作反馈定义
4. 状态变化规则
5. 错误提示文案

要求：
- 考虑各种边界情况
- 定义清晰的反馈机制
- 保持与现有设计一致
```

---

### Step 5: 数据建模 (30分钟)

**任务**: 设计数据模型

**输入**:
- 功能模块
- 业务流程

**输出**:
- 数据实体定义
- ER图
- `006-database-design.md` (如未存在)

**提示词**:
```
为以下功能设计数据模型：
{功能描述}

输出：
1. TypeScript接口定义
2. 实体关系图（Mermaid ER图）
3. 关键字段说明
4. 索引设计建议

约束：
- 使用SQLite
- 考虑离线场景
- 遵循现有命名规范
```

---

### Step 6: API设计 (30分钟)

**任务**: 设计API接口

**输入**:
- 数据模型
- 功能模块

**输出**:
- API规范
- `007-api-design.md` (如未存在)

**提示词**:
```
设计【{功能模块}】的API接口：

每个接口需包含：
1. 接口路径和方法
2. 请求参数（必需/可选）
3. 响应数据结构
4. 错误码定义
5. 调用示例

要求：
- RESTful风格
- 统一响应格式
- 包含错误处理
```

---

### Step 7: PRD组装 (30分钟)

**任务**: 整合所有内容生成完整PRD

**输入**:
- PRD大纲
- 所有子文档
- 模板

**输出**:
- 完整PRD `005-PRD.md` 或具体功能PRD

**提示词**:
```
整合以下内容生成完整PRD：

1. 概述: {概述内容}
2. 模块规格: {模块内容}
3. 业务流程: {流程内容}
4. 交互设计: {交互内容}
5. 数据设计: {数据内容}

要求：
1. 使用 templates/prd-template.md 格式
2. 确保章节间逻辑连贯
3. 添加适当的过渡语句
4. 检查术语一致性
5. 完善验收标准

输出完整的Markdown文档。
```

每个Step完成后进行自检：

### Step 1 检查点

- [ ] 章节结构合理

### Step 2 检查点
- [ ] 模块职责清晰
- [ ] P0功能已识别

### Step 3 检查点
- [ ] 流程逻辑完整
- [ ] 异常分支已考虑

### Step 4 检查点
- [ ] 交互细节完整
- [ ] 边界情况已处理

### Step 5 检查点
- [ ] 实体关系正确
- [ ] 字段定义清晰

### Step 6 检查点
- [ ] API设计符合规范
- [ ] 错误处理完整

### Step 7 检查点
- [ ] 文档格式正确
- [ ] 验收标准可量化

```
  ├─ module-specs.md          # 模块规格
  ├─ interaction-flow.md      # 交互流程

```

## 常见问题

### Q1: 如何处理复杂功能的PRD？

复杂功能可以：
1. 拆分为多个子功能的PRD
2. 先输出概要PRD，再输出详细PRD
3. 使用分阶段交付（MVP + 迭代）

### Q2: 如何确保设计一致性？

1. 参考已有文档的设计模式
2. 使用统一的术语和命名规范
3. 交叉检查相关文档

### Q3: 如何处理需求变更？

1. 记录变更内容
2. 评估影响范围
3. 更新相关文档
4. 版本号递增
5. 归档旧版本
