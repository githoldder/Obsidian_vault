## Q1：Web端职责范围

### 问题
> 我只负责超级管理员还是包括管理员和普通用户？

### 答案

**Web端涵盖全部三个角色**，但根据需求优先级，建议分期实现：

| 角色            | 职责定位           | Web端优先级    |
| ------------- | -------------- | ---------- |
| **超级管理员（民警）** | 全局管理、预警裁决、账号分发 | 🔴 高（本期核心） |
| **管理员（网格员）**  | 区域数据管理、审核、报表导出 | 🟡 中       |
| **普通用户（二房东）** | 信息上报、查看记录      | 🟢 可小程序替代  |

### 开发策略建议

**方案A（推荐）**：Web端仅实现超级管理员功能，普通用户功能由小程序承载
**方案B**：Web端实现全部三个角色（工作量×2）

> **建议选方案A**，原因：
> - 原型已完成小程序端开发
> - 二房东使用移动端更便捷
> - 减少Web端复杂度

### ✅ 已确认
- [x] **方案A**：Web端仅实现**管理员**功能，普通用户功能由小程序承载

> 注：普通用户（二房东）通过小程序操作，Web端不实现普通用户功能

## Q2：预警裁决机制

### 问题
> 预警裁决到底是要干什么，预警什么，裁决什么？

### 答案

根据需求文档，预警裁决包含以下场景：

#### 预警触发条件

| 预警类型 | 触发条件 | 预警级别 |
|----------|----------|----------|
| **未成年人预警** | 单独居住的未成年人（年龄<18） | ⚠️ 黄色 |
| **身份证重复预警** | 同一身份证号在不同房源登记 | 🔴 红色 |
| **房源异常预警** | 房源被标记为"经常报警/犯罪" | 🔴 红色 |
| **超员预警** | 房间超过2人 / 整房超过10人 | ⚠️ 黄色 |

#### 裁决流程

```
预警触发 → 超级管理员查看详情 → 裁决处理
                              ├── 确认风险 → 可自定义标签（默认无标签，用户可自定义添加，如果有历史标签记录可以下拉选中）
                              标记管控级别（一般/关注/管控）标签内容定义完后的操作，可以选择当前的标签关注度优先级，对应淡黄色、橙黄色、深红色
                              ├── 误报 → 取消预警
                              └── 需核实 → 派发网格员核查
```

#### Web端需要实现

| 功能   | 说明               |
| ---- | ---------------- |
| 预警列表 | 展示所有待处理预警        |
| 预警详情 | 查看预警来源、人员信息、关联房源 |
| 裁决操作 | 通过/驳回/派发核查       |
| 标签标注 | 标注风险等级           |

### ✅ 已确认

| 确认项 | 结论 |
|--------|------|
| **超员阈值** | 2人/房间、10人/套，超过即触发预警 |
| **预警颜色** | 人员性质问题 → 黄色；房源性质问题 → 红色 |
| **优先级** | 房源问题优先处理 |
| **标签与颜色关系** | 标签等级（淡黄/橙黄/大红）**仅用于预警详情页**，不参与楼栋主色渲染；楼栋颜色只由异常类型决定 |

#### 预警触发流程

```
用户端登记信息
    ↓
未达到异常阈值 → 正常弹窗显示新增/删除信息
    ↓
达到异常阈值 或 网格员上推提交审核
    ↓
触发预警机制 → Web端弹窗提示
    ↓
房源状态自动判断
    ├── 房源异常问题 → 🔴 红色
    └── 人员异常问题 → 🟡 黄色
```

#### 预警处理界面

| 功能 | 说明 |
|------|------|
| **历史记录** | 显示历史处理预警信息，默认按最新未处理排序 |
| **标签选择** | 可选择已定义标签或自定义标签 |
| **标签等级** | 一般(淡黄) / 关注(橙黄) / 管控(大红)，与标签强绑定 |
| **备注信息** | 可选输入 |

#### 标签系统

| 功能        | 说明                 |
| --------- | ------------------ |
| **增删改查**  | 完整的标签管理功能          |
| **自定义标签** | 预警处理时可即时创建         |
| **标签管理**  | 主动设置管理标签（添加/删除/修改） |
| **标签查找**  | 通过等级查找 + 标签模糊搜索    |

> **关键原则**：标签等级颜色与楼栋颜色**独立显示，互不干扰**

## ==Q3：账号分发机制==

### 问题
> 账号是怎么分发？要发给谁？是二房东先申请账号然后超级管理员 accept 吗？

### 答案

根据需求文档，账号分发流程如下：

#### 账号体系

| 角色            | 创建方式         | 审批流程      |
| ------------- | ------------ | --------- |
| **管理员（网格员）**  | 超级管理员手动创建    | 直接创建，无需审批 |
| **普通用户（二房东）** | 自主注册 / 管理员邀请 | 需审核       |

#### 二房东账号流程

```
二房东申请注册
    ↓
超级管理员/管理员审核（核实是否为真实二房东）
    ↓
审核通过 → 分配房源绑定
审核拒绝 → 返回原因
```

#### Web端需要实现

| 功能 | 说明 |
|------|------|
| 账号注册审批列表 | 展示待审批的账号申请 |
| 审批操作 | 通过/拒绝/查看详情 |
| 账号分配 | 将账号与房源绑定 |
| 账号管理 | 增删改、角色变更、禁用启用 |

| 确认项        | 结论                               |
| ---------- | -------------------------------- |
| **账号分发方式** | 系统采用分发式账号体系，由超级管理员统一生成账号并分发至各级用户 |
| **原型阶段**   | 账号分发功能**后期实现**，原型阶段先不考虑          |
| **技术路线**   | 超级管理员统一生成并分发                     |


> **当前阶段**：账号管理功能可简化，预留接口即可

## Q4：颜色逻辑冲突处理

### 问题
> 房子不安全，人也有问题怎么办？是加权优先还是叠加？

### 答案

#### 当前颜色规则

| 状态 | 颜色 | 适用对象 |
|------|------|----------|
| 正常 | 🟢 绿色 | 房源/人员均无异常 |
| 房源不安全 | 🔴 红色 | 房源被标记特殊处理 |
| 人员不安全 | 🟡 黄色 | 居住人员存在风险 |

#### 冲突处理方案

**推荐方案：叠加原则 + 优先级显示**

```
房源颜色判断逻辑：

if (房源标记为特殊处理) {
    显示 = 红色
} else if (存在不安全人员) {
    显示 = 黄色
} else {
    显示 = 绿色
}
```

| 场景 | 结果颜色 | 说明 |
|------|----------|------|
| 房源异常 + 人员异常 | 🔴 红色 | 房源异常优先 |
| 房源正常 + 人员异常 | 🟡 黄色 | 人员异常 |
| 房源异常 + 人员正常 | 🔴 红色 | 房源异常 |
| 房源正常 + 人员正常 | 🟢 绿色 | 正常 |

#### 标签分级颜色（独立于房源颜色）

| 级别 | 颜色 | 说明 |
|------|------|------|
| 一般 | 淡黄色 | 轻微关注 |
| 关注 | 橙黄色 | 中度关注 |
| 管控 | 深红色 | 高度管控 |

> 标签颜色与房源颜色为**独立维度**，可在房源上同时显示多个标签

### ✅ 已确认

| 确认项 | 结论 |
|--------|------|
| **颜色优先级** | 房源异常优先（红色 > 黄色 > 绿色） |
| **标签颜色独立性** | ✅ **独立显示** |

#### 最终颜色逻辑

**楼栋主色（异常类型决定）：**

| 场景 | 结果颜色 | 说明 |
|------|----------|------|
| 房源异常 + 人员异常 | 🔴 红色 | 房源异常优先 |
| 房源正常 + 人员异常 | 🟡 黄色 | 人员异常 |
| 房源异常 + 人员正常 | 🔴 红色 | 房源异常 |
| 房源正常 + 人员正常 | 🟢 绿色 | 正常 |

**标签颜色（预警详情页显示）：**

| 级别 | 颜色 | 说明 |
|------|------|------|
| 一般 | 淡黄色 | 轻微关注 |
| 关注 | 橙黄色 | 中度关注 |
| 管控 | 深红色 | 高度管控 |

> **关键原则**：标签等级颜色**不参与楼栋主色渲染**，两者独立显示，互不干扰

| **房源优先** | 房源异常（红）> 人员异常（黄）> 正常（绿） |
| **地图核心** | 首页以地图可视化为核心，其他图表作为占位 |
| **角色隔离** | 管理员仅能看到权限区域内的数据 |
| **预警流程** | 弹窗提示 → 进入处理界面 → 标签标注 → 状态更新 |
