# POP3（邮局协议第3版）

## 📖 定义-解释-示例

### 什么是 POP3？

**POP3**（Post Office Protocol version 3）是互联网电子邮件**接收和下载**协议，运行在应用层，默认端口 **110**（明文）/ **995**（SSL/TLS）。POP3 采用**离线模式**：客户端连接到服务器，将邮件**全部下载到本地**，默认下载后**从服务器删除**。这是它和 IMAP 最本质的区别。

### POP3 的工作模型

想象传统邮局的运作逻辑：
1. 邮件存储在"邮局"（邮件服务器）你的"信箱"里
2. 你带着"提货本"（邮件客户端）去"取信"
3. POP3 的做法：把所有信取出来带走，邮箱清空
4. IMAP 的做法：在邮局看信，但不带走原件

### POP3 的会话过程

POP3 也是命令-响应文本协议，比 SMTP 更简单：

```
S: +OK POP3 server ready
C: USER alice         ← 用户名
S: +OK
C: PASS ******        ← 密码（明文，除非 SSL）
S: +OK Mailbox locked
C: STAT               ← 查询邮件数量&总大小
S: +OK 3 45221       ← 3封邮件，共45221字节
C: LIST               ← 列出所有邮件大小
S: +OK
S: 1 12040
S: 2 18200
S: 3 14981
S: .
C: RETR 1             ← 取回第1封邮件
S: +OK 12040 octets
S: From: ...
S: To: ...
S: (complete message)
S: .                  ← 单独一行 `.` 结束
C: DELE 1             ← 标记第1封邮件为删除
S: +OK
C: QUIT               ← 退出，执行 DELE 标记
S: +OK
```

**重要行为**：`DELE` 只是**标记删除**，实际删除发生在 `QUIT` 命令时。如果在 `QUIT` 之前连接中断，邮件不会被删除。这是 POP3 的安全设计。

### POP3 的核心特性

**1. 下载后删除（默认模式）**
默认情况下，客户端下载邮件后服务器上的邮件被删除。这意味着：
- 换设备后看不到之前的邮件
- 节省服务器存储空间
- 适合"一台电脑走天下"的时代

**2. 保留副本选项**
大多数 POP3 客户端提供"在服务器上保留副本"的选项，但这不是协议本身的功能，是客户端的实现。

**3. 离线阅读**
邮件下载到本地后，无需网络连接即可阅读。这是 POP3 在拨号上网时代的重要优势——趁夜深人静拨号下载邮件，白天离线阅读。

**4. 一次性认证**
认证后加锁整个邮箱，避免并发冲突。同一时刻只有一个 POP3 会话能访问邮箱。

### POP3 与 SMTP 的分工

| 协议 | 角色 | 端口 | 方向 |
|------|------|------|------|
| SMTP | 发送邮件 | 25/465/587 | 客户端→服务器（推） |
| POP3 | 接收邮件 | 110/995 | 客户端→服务器（拉/下载） |

一封邮件从 Alice 到 Bob 的完整路径：Alice 用 SMTP 发送 → Alice 的 SMTP 服务器转发 → Bob 的 SMTP 服务器接收 → 存入 Bob 的邮箱 → Bob 用 POP3 下载到本地。

### POP3 的优势与劣势

**优势**：
- 协议简单，实现成本低
- 邮件存储在本地，不依赖服务器存储
- 离线阅读，不需要持续网络连接
- 适合服务器存储空间有限的场景

**劣势**：
- **单设备局限**：邮件下载到本地后，换设备看不到
- **无服务器端状态同步**：已读/未读、标记、文件夹等信息本地存储
- **无服务器端搜索**：所有搜索依赖本地索引
- **不适合多设备时代**：现代人手机+平板+电脑三设备场景，POP3 表现糟糕

### POP3 的现代地位

在当今多设备、云同步的时代，POP3 已被 **IMAP** 全面取代。Google（Gmail）、Microsoft（Outlook.com）、Apple（iCloud）等主流邮件服务**默认推荐 IMAP**。POP3 仅在一些特殊场景中仍有用武之地：对隐私极端敏感（邮件不下放云端）、服务器存储极度受限、只需要在单一设备上访问邮件。
