# Inline 字段：Obsidian 中的嵌入式元数据 📌

> `key:: value`——把结构化数据直接嵌入笔记正文，让每一段文字都成为可查询的数据点

## 📖 定义与解释

**Inline 字段**是 Obsidian 中 Dataview 插件支持的**嵌入式元数据格式**，语法为 `字段名:: 字段值`，直接写在笔记正文的任意位置。与 YAML Frontmatter 不同，Inline 字段不是集中在笔记顶部，而是**散布在正文中**，与具体内容紧密绑定。

这一设计的核心哲学是：**元数据不应该远离它描述的内容**。如果你在笔记某个段落中提到"这个概念我还不太理解"，你可以在旁边标注 `理解程度:: 30%`。三个月后 Dataview 查询可以帮你列出所有"理解程度低于 50%"的知识点，这些就是复习的优先目标。

## 🔬 定义、解释与示例

### 基本语法

```
字段名:: 字段值
```

关键规则：
- 字段名和值之间用**双冒号** `::` 分隔（单冒号不生效）
- 字段名中不能包含空格（如需分隔，用下划线或连字符）
- 字段值可以是**数字、文本、日期、链接**等多种类型

### 实际示例

```markdown
## 贝叶斯定理

贝叶斯定理描述了在已知某些条件下某事件发生的概率。

理解程度:: 75%
复习次数:: 3
上次复习:: 2026-06-20
关联概念:: [[条件概率]]
掌握状态:: 已掌握
```

Dataview 会自动识别 `理解程度`、`复习次数`、`上次复习`、`关联概念`、`掌握状态` 为五个独立的元数据字段，可以在查询中使用。

### Inline 字段的自动类型推断

Dataview 会根据值的格式自动推断类型：
- `42` 或 `3.14` → **数字类型**（Number）
- `2026-07-03` → **日期类型**（Date）
- `[[某笔记]]` → **链接类型**（Link）
- `已完成` 或 `高` → **文本类型**（Text）
- `true` / `false` → **布尔类型**（Boolean）

这意味着 `复习次数:: 3` 在 Dataview 中可以用于数值比较（`WHERE 复习次数 > 2`），而 `掌握状态:: 已掌握` 可以用于文本匹配（`WHERE 掌握状态 = "已掌握"`）。

## 📐 步骤指导：如何有效使用 Inline 字段

### 第一步：确定要追踪的维度

不要一上来就给每个段落加十个字段。先问自己三个问题：

1. **我以后会按这个维度搜索吗？** ——如果"阅读日期"你不会用来筛选或排序，就不需要加。
2. **这个值会随时间变化吗？** ——固定不变的信息（如书籍作者）用 Frontmatter 更合适；会变化的（如阅读进度）用 Inline 字段。
3. **这个字段和特定的内容段落绑定吗？** ——如果绑定，用 Inline；如果描述整篇笔记，用 Frontmatter。

### 第二步：套用模式模板

以下是几个高频使用模式，可以直接套用：

**学习追踪模式：**
```
理解程度:: 50%
复习次数:: 2
上次复习:: 2026-06-15
掌握状态:: 学习中
```

**阅读追踪模式：**
```
阅读进度:: 60%
评分:: 4.0
关键洞见:: [[某个概念]]
摘录日期:: 2026-07-01
```

**项目状态模式：**
```
完成度:: 80%
当前阶段:: 开发中
阻塞项:: 等待API文档
下一步:: 完成单元测试
```

### 第三步：创建配套的 Dataview 查询

Inline 字段的价值体现在**查询和聚合**上。下面是几个实用的查询模板：

**列出所有学习中的概念：**
````markdown
```dataview
TABLE 理解程度, 复习次数, 上次复习
FROM "002_知识体系构建"
WHERE 掌握状态 = "学习中"
SORT 理解程度 ASC
```
````

**找出即将需要复习的知识点：**
````markdown
```dataview
TABLE 上次复习, 理解程度
FROM "002_知识体系构建"
WHERE 上次复习 < date(today) - dur(7 days)
SORT 上次复习 ASC
```
````

**阅读进度仪表盘：**
````markdown
```dataview
TABLE 阅读进度, 评分, 关键洞见
FROM "阅读笔记"
WHERE 阅读进度 AND 阅读进度 < 100
SORT 评分 DESC
```
````

## ⚖️ 比较与对比：Inline 字段 vs YAML Frontmatter

| 维度 | Inline 字段 | YAML Frontmatter |
|------|------------|-----------------|
| **位置** | 正文任意位置 | 笔记顶部 `---` 包裹 |
| **粒度** | 段落/章节级 | 整篇笔记级 |
| **适合场景** | 追踪变化状态、段落级标注 | 笔记级属性（标签、日期、作者） |
| **可见性** | 渲染可见（除非 CSS 隐藏） | 阅读视图下折叠 |
| **可编辑性** | 直接在正文中修改 | 需要进入编辑/源码模式 |
| **查询性能** | 略低于 Frontmatter（需扫描全文） | 较高（位于固定位置） |
| **导入导出** | Obsidian/Dataview 特有格式 | YAML 标准格式，工具兼容性好 |

**选择策略**：
- ✅ 用 **Frontmatter** 管理笔记级元信息：标题、标签、创建日期、领域分类
- ✅ 用 **Inline 字段** 管理段落级动态信息：理解程度、阅读进度、评分、复习状态
- ✅ **两者互补**：一篇笔记的"类型"标签用 Frontmatter，其中每个知识点的"掌握程度"用 Inline 字段

## 🎯 案例：用 Inline 字段构建间隔复习系统

假设你正在学习人工智能相关概念，你想基于艾宾浩斯遗忘曲线建立一个简易的间隔复习提醒系统：

**在笔记中标注：**
```markdown
## 卷积神经网络（CNN）

卷积神经网络通过卷积核提取局部特征。

理解程度:: 60%
复习次数:: 1
上次复习:: 2026-07-01
下次复习:: 2026-07-04
掌握状态:: 学习中
```

**创建复习仪表盘：**
````markdown
```dataview
TABLE 理解程度, 复习次数, 上次复习
FROM "005-人工智能"
WHERE 掌握状态 != "已掌握"
SORT 下次复习 ASC
LIMIT 10
```
````

这样你每天打开这个仪表盘，就能看到"今天需要复习哪些知识点"——不需要任何外部 App，完全在 Obsidian 内闭环。

## ⚠️ 常见问题

**Q: Inline 字段在阅读视图中很碍眼怎么办？**
A: 可以用 CSS 片段（Snippet）隐藏或淡化 Inline 字段的显示。在 `.obsidian/snippets/` 下创建 CSS 文件，将 `::` 和值改为浅灰色。

**Q: 字段名拼写不一致怎么办？**
A: 这是最常犯的错误——`理解程度:: 80%` 和 `理解度:: 60%` 会被 Dataview 视为两个不同字段。解决方案：建立一份**字段名词典**笔记，列出所有正在使用的字段名，新增字段时先查词典。

**Q: 一个笔记中 Inline 字段太多会影响查询性能吗？**
A: 普通用户（< 1000 篇笔记，每篇 < 20 个 Inline 字段）基本感受不到性能影响。如果笔记库达到万篇级别，考虑将高频查询的字段迁移到 Frontmatter。
