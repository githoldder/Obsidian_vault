# 防火墙（Firewall）

## 📖 定义-解释-示例

### 什么是防火墙？

**防火墙**是网络安全的第一道防线，它在不同安全域之间建立**受控的访问屏障**，根据预定义的安全策略决定允许或拒绝哪些流量通过。防火墙可以是一个独立的硬件设备，也可以是运行在操作系统上的软件，也可以是云上的虚拟化服务。不论形态如何，核心逻辑只有一句话：**默认拒绝一切，只放行明确允许的**（白名单策略）。

### 防火墙的演进——从简单包过滤到下一代

**第一代：包过滤防火墙（Packet Filter）**
- 工作在 L3/L4，检查每个包的五元组：源 IP、目的 IP、源端口、目的端口、协议
- 纯用 ACL 匹配，速度快但能力有限
- 无法理解应用层内容，不知道 HTTP 请求是正常的还是 SQL 注入
- 无法跟踪连接状态（FTP 这种动态协商端口的协议很痛苦）

**第二代：状态检测防火墙（Stateful Inspection）**
- 维护**连接状态表**（TCP 连接的 SYN → SYN-ACK → ESTABLISHED → FIN 等生命周期）
- 只检查连接的首包，后续包直接匹配状态表放行
- 可以自动放行已建立连接相关的返回流量，避免为每个方向都写规则
- Linux `iptables` 的 conntrack 模块就是典型的状态检测实现
- 关键局限：仍然只看 L3/L4，不关心应用层内容

**第三代：应用层防火墙（Application-Level Gateway / Proxy Firewall）**
- 工作在 L7，理解 HTTP、FTP、DNS、SMTP 等应用协议
- 可以过滤特定 URL 路径、阻止 SQL 注入、检测恶意文件上传
- 作为代理（Proxy）终结客户端连接并重建到服务器的连接，可以深度检查内容
- 代价：更高延迟、更高 CPU 消耗、必须支持每一种应用协议

**第四代：下一代防火墙（NGFW，Next-Generation Firewall）**
- 融合包过滤 + 状态检测 + 应用识别 + IPS + 威胁情报
- 应用识别（App-ID）：不仅仅是"端口 443"，而是识别出"这是 Facebook 的 TLS 流量"
- 用户识别（User-ID）：不只是"IP 10.0.0.5"，而是"员工张三"
- 集成的 IPS/IDS、恶意软件沙箱、URL 过滤、SSL 解密检查
- 代表产品：Palo Alto Networks、Fortinet FortiGate、Check Point

### 防火墙的部署模式

**网络层防火墙**：
- 透明地嵌入网络路径中
- 路由模式：防火墙充当路由器，不同接口在不同子网
- 透明模式（桥接模式）：防火墙像交换机一样工作，不改变 IP 拓扑，即插即用

**主机防火墙**：
- 运行在受保护的主机上
- `iptables`/`nftables`（Linux）、`Windows Firewall`、`pf`（macOS/BSD）
- 单独的主机防火墙不能防御网络级别的攻击，必须与网络防火墙配合

**云防火墙 / 安全组**：
- AWS Security Group、Azure NSG、阿里云安全组
- 分布式虚拟防火墙，每个虚拟机有自己的入站/出站规则
- 不需要集中的物理设备，但管理分散

### iptables 与 nftables 示例

Linux 防火墙的经典 CLI：

**`iptables` 示例**（传统框架）：
```bash
# 默认丢弃所有入站流量
iptables -P INPUT DROP

# 允许已建立连接的相关流量
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 允许来自 lo 接口的所有流量
iptables -A INPUT -i lo -j ACCEPT

# 允许来自 10.0.0.0/24 子网的 SSH（端口22）
iptables -A INPUT -s 10.0.0.0/24 -p tcp --dport 22 -j ACCEPT

# 拒绝来自特定 IP 的所有流量
iptables -A INPUT -s 192.168.1.100 -j DROP
```

`iptables` 的链式结构：PREROUTING → INPUT → FORWARD → OUTPUT → POSTROUTING。每个链包含按序匹配的规则，匹配到第一条就停止。

**`nftables` 示例**（现代替代，合并 iptables/ip6tables/arptables/ebtables）：
```bash
nft add table inet my_filter
nft add chain inet my_filter input { type filter hook input priority 0\; policy drop\; }
nft add rule inet my_filter input ct state established,related accept
nft add rule inet my_filter input iif lo accept
```

### 防火墙规则设计原则

**1. 最小权限（Least Privilege）**
只放行业务必需的端口和协议。开发环境能通 22，生产环境就要问问：真的需要直接 SSH 进生产服务器吗？

**2. 默认拒绝（Default Deny）**
最后一条规则应该是 `DROP ALL`。没有被明确允许的就是不允许。白名单模式的本质。

**3. 分层防御（Defense in Depth）**
不要只有一层防火墙。外围防火墙（边界）+ 主机防火墙（服务器）+ 应用层 WAF（Web 应用防火墙）形成纵深。

**4. 最小化暴露面**
数据库端口（3306/5432/27017）永远不要暴露到公网！这应该是刻在骨子里的信条。

### 防火墙的局限性——它不能做什么？

- 防火墙不能防御**内部威胁**（已获得合法访问权限的攻击者）
- 防火墙不能防御**应用层漏洞**（需 WAF 配合）
- 防火墙不能防御**加密流量中的攻击**（除非做 SSL 解密检查，这带来隐私和性能代价）
- 防火墙不能替代**安全意识**（员工点钓鱼邮件，防火墙帮不了你）
- 防火墙是**必要的但不充分**的安全措施。它只是纵深防御体系中的一环，而非全部
