# DoS 与 DDoS 攻击

## 📖 问题-答案 / 案例分析

### 什么是 DoS 攻击？

**DoS（拒绝服务攻击）** 的核心目标：让合法的用户**无法正常访问服务**。手段可以是耗尽目标的计算资源、占满网络带宽、利用协议漏洞使服务崩溃，或者利用应用层的逻辑缺陷让服务器忙于处理无效请求。

**DoS vs DDoS**：DoS 是单点攻击，一台机器搞垮一个服务。DDoS（分布式拒绝服务）是多对一攻击——利用僵尸网络（Botnet）的成千上万台被控设备同时向目标发起流量，规模可达 Tbps 级别。DDoS 是现代互联网最严重的威胁之一。

### DoS/DDoS 攻击的分类

**1. 带宽耗尽型攻击（Volumetric）**

**UDP 洪水**：
攻击者向目标随机端口发送大量 UDP 数据包。每包到达时，目标主机会检查该端口是否有应用监听——没有？回复 ICMP Destination Unreachable。成百万包打过来 → CPU 被占满处理这些回应 + 带宽被占满。

**ICMP 洪水 / Ping 洪水**：
持续向目标发送大量 ICMP Echo Request（ping），目标忙于回复 Echo Reply。

**DNS 放大攻击（DNS Amplification）**：
这是最可怕的带宽攻击类型之一。攻击者伪造目标的 IP 地址作为源地址，向开放 DNS 解析器发送小型 DNS 查询（约 60 字节）。DNS 解析器将大型响应（可达 4000 字节）返回给目标。**放大系数 60 倍+**。更可怕的例子：Memcached 放大攻击（放大系数可达 51,000 倍）。攻击者用 1 Gbps 的流量发动攻击，目标承受 51 Gbps。

**2. 协议攻击（Protocol / State-Exhaustion）**

**SYN 洪水**：
TCP 三次握手的第一步：客户端发 SYN → 服务器回 SYN+ACK 并分配一个半开连接表条目 → 等客户端的 ACK。如果客户端永远不回 ACK（而是继续发 SYN），服务器的半开连接表很快被占满（通常只有几千到几万条条目）。此时新的合法连接无法建立，服务对外表现为"不可用"。

**防御手段**：
- **SYN Cookie**：服务器不立即分配资源，而是将连接信息编码到返回的 SYN+ACK 的序列号中。只有收到合法的 ACK 后才真正分配资源
- **SYN Proxy**：中间设备替服务器维护状态，只把完整三次握手的连接交给服务器
- 调整 `tcp_max_syn_backlog` 和 `tcp_synack_retries`（治标不治本）

**3. 应用层攻击（Application Layer）**

**HTTP 洪水**：
攻击者发送大量看起来完全正常的 HTTP GET/POST 请求——每个请求都像真实用户在访问网站。因为请求看起来合法，防火墙和 IPS 很难区分攻击流量和正常流量。

**Slowloris**：
极其狡猾的攻击方式。攻击者打开大量到目标 HTTP 服务器的连接，然后极其缓慢地发送 HTTP 请求头——每次发一个字节，间隔数秒。服务器为"等待完成请求"保持着大量半开连接，耗尽连接池。Slowloris 只需要一台普通电脑的带宽就可以打挂一台高性能 Web 服务器。

**R-U-Dead-Yet（R.U.D.Y.）**：
类似手法，通过在 HTTP POST 中发送极慢的请求体（Content-Length 很大但每秒只发 1 字节），耗尽服务器连接池。

**HTTP/2 Rapid Reset（2023 年 10 月公开）**：
HTTP/2 中，客户端可以在一个连接上快速创建和取消大量 stream。攻击者瞬间打开海量 stream 然后立即 RST_STREAM 取消——在应用层看来这毫发无伤，但中间代理和服务器负载均衡器在协议层面被压垮。Google、AWS、Cloudflare 都被此攻击严重冲击，CVE-2023-44487 被评为 CVSS 7.5。

### DDoS 攻击的防御体系

**1. 黑洞路由（Blackhole / Null Routing）**
最简单的防御：把目标 IP 的路由指向空端口（流量直接丢弃）。副作用：所有流量都被丢弃，合法用户也被牺牲了。适用于极端情况——宁可自己不可用也不让攻击流量污染上游。

**2. 速率限制（Rate Limiting）**
在防火墙/路由器上限制特定类型的流量速率——每秒最多允许多少个 SYN 包、ICMP 包。有效抵抗简单的洪水攻击，但攻击者可以分散源 IP 将速率控制绕过。

**3. 云清洗（Cloud Scrubbing）**
专业 DDoS 防护服务（Cloudflare、Akamai、AWS Shield Advanced）。通过 BGP 将目标网段的流量引导到清洗中心，用巨大的网络容量吸收攻击流量，过滤后只将干净流量送回源站。这是目前对付 Tbps 级别 DDoS 的标准手段。

**4. CDN 与任播（Anycast）**
内容分发到全球节点，攻击流量被分散。任播让同一 IP 在全球多个位置同时被宣告，流量被最近的路由器吸收——攻击者必须同时攻击所有节点。

**5. WAF（Web 应用防火墙）**
针对应用层攻击（HTTP 洪水、Slowloris），WAF 可以在 HTTP 层面识别异常请求模式并拦截。

### 防御者的视角——三层纵深

```
第一层：ISP/上游网络的流量清洗 → 阻挡 Tbps 级别的大流量洪水
第二层：边界防火墙的速率限制和 SYN Cookie → 防止协议攻击穿透
第三层：应用层 WAF 和超时策略 → 对抗 Slowloris 和 HTTP 洪水等精巧攻击
```

没有单一一层能防所有攻击。纵深防御，逐层过滤。

### 攻击方的视角——DDoS 如何被发动？

1. 攻击者通过恶意软件感染互联网上的脆弱设备（IoT 摄像头、路由器、未打补丁的服务器）
2. 被感染的设备组成**僵尸网络（Botnet）**，等待 C2（Command & Control）服务器的指令
3. 攻击者向 C2 下达攻击指令（目标 IP、攻击类型、持续时间）
4. 数千至数百万台僵尸设备同时向目标发送攻击流量
5. **DDoS 即服务（Booter/Stresser）**：在暗网上，花几美元就能购买 DDoS 攻击服务

### 现实案例

- **2016 年 Dyn DDoS**：Mirai 僵尸网络利用数百万 IoT 设备的默认密码感染，攻击 DNS 服务商 Dyn，导致 Twitter、Netflix、Reddit、GitHub 等大面积宕机。攻击峰值 ~1.2 Tbps
- **2018 年 GitHub DDoS**：Memcached 放大攻击，峰值 1.35 Tbps（当时历史最高记录），GitHub 依靠 Akamai 的 DDoS 清洗服务在几分钟内恢复
- **2023 年 HTTP/2 Rapid Reset**：利用协议漏洞，无需大量带宽就能对服务器造成毁灭性打击
