# 网卡（NIC / Network Interface Card）

## 📖 定义-解释-示例

### 什么是网卡？

**网卡**（NIC，网络接口控制器）是计算机与网络之间的**物理接口**，工作在数据链路层和物理层。网卡的一端是计算机内部总线（PCIe/USB），另一端是网络介质（以太网/光纤/Wi-Fi）。它的核心使命：将计算机的数据转换为符合网络协议的信号发出去，将网络传来的信号转换为计算机能理解的数据收进来。

### 网卡的硬件架构

现代网卡的内部结构：

**1. MAC 控制器（L2 功能）**
- 封装/解封装以太网帧（加/去帧头和 FCS）
- CSMA/CD（半双工模式下）或全双工流量控制
- MAC 地址过滤：只有目标 MAC 是自身或广播/组播的帧才会被接收，其余直接丢弃
- VLAN 标签的添加和剥离（硬件卸载）
- 校验和卸载（Checksum Offloading）：TCP/UDP 校验和计算由网卡硬件完成，而非 CPU

**2. PHY（物理层收发器）**
- 将 MAC 层的比特流转换为电信号（铜缆）或光信号（光纤）
- 自适应速率协商（Auto-Negotiation）：与他端设备协商最佳的速率和双工模式
- 信号编码：1000BASE-T 使用 PAM-5 编码（5 级脉冲幅度调制，4 对线同时传输）

**3. DMA 引擎（直接内存访问）**
- 网卡直接向系统内存读写数据，不经过 CPU
- 发送：DMA 从内存的发送环形缓冲区取数据 → 网卡 FIFO → 发送
- 接收：收到的数据 → 网卡 FIFO → DMA 写入内存的接收环形缓冲区 → 中断通知 CPU

### 网卡的缓冲区与中断机制

**环形缓冲区（Ring Buffer）**：
- 驱动在内存中分配固定大小的环形描述符队列
- 发送环（TX Ring）：每个描述符指向待发送的数据包
- 接收环（RX Ring）：每个描述符指向空的缓冲区，收到数据时网卡写入其中
- 环满了？→ 新包没法 DMA 写进去 → **丢包**。`ifconfig` 中看到的 `dropped` 计数器就是这么来的

**中断 vs 轮询**：
- 传统方式：每收一个包就中断一次 CPU。高流量时中断风暴会把 CPU 打满（中断活锁）
- **NAPI（New API）**：Linux 内核的优化机制。高负载时关闭中断，改用轮询（polling）批量处理数据包。低负载时恢复中断。在高 PPS（每秒包数）场景下，NAPI 是网卡性能的核心决定因素

### 网卡的关键性能指标

**1. 线速（Wire Speed）**
物理层最大比特率：1 Gbps、10 Gbps、25 Gbps、40 Gbps、100 Gbps。但线速不等于实际吞吐量——你还要考虑帧间间隙（IFG，12 字节）、前导码（8 字节）和帧头开销。

**2. PPS（每秒包数 / Packets Per Second）**
小包场景（64 字节）的核心限制。64 字节是最小以太网帧（64 字节 + 20 字节前导码+IFG = 84 字节线速负载）：

- 1 Gbps：理论最大 1.488 Mpps（百万包/秒）
- 10 Gbps：理论最大 14.88 Mpps
- 100 Gbps：理论最大 148.8 Mpps

如果网卡或 CPU 处理不了这个 PPS（中断数过高、缓冲区太小），即使总吞吐量远没达线速也会丢包。

**3. 卸载功能（Offloading）**
现代网卡用硬件接管了大量原本 CPU 需要做的工作：
- **TSO（TCP Segmentation Offload）**：网卡将大块数据自动分割为 MTU 大小的 TCP 段，CPU 只需交付一个"巨型数据块"
- **LRO（Large Receive Offload）**：网卡将到达的多个 TCP 段合并，CPU 一次收到一个大块
- **Checksum Offload**：TCP/UDP/IP 校验和由网卡计算
- **RSS（Receive Side Scaling）**：收到的数据包按 tuple（源/目 IP + 端口）哈希到不同接收队列，每个队列绑定不同 CPU 核心，多核并行处理

### 网卡的类型

**有线以太网网卡**：
- **1GbE**：最普及，RJ-45 接口，Cat 5e 线缆，占桌面和服务器市场主流
- **10GbE**：服务器标配，SFP+（光纤）或 RJ-45（Cat 6a），虚拟化和存储网络
- **25/40/50/100GbE**：数据中心，QSFP28 等接口形态，云计算和 HPC

**无线网卡**：
- 内置（笔记本/手机）：集成在主板上，通过内部天线收发
- 外置（USB Wi-Fi 适配器）：便携但性能弱于内置
- 关键规格：Wi-Fi 代际（6/6E/7）、频段支持（2.4/5/6 GHz）、MIMO 流数（2×2/4×4）、蓝牙版本

**光纤网卡（HBA 变体）**：
- FC HBA（光纤通道主机总线适配器）：SAN 存储网络专用，不是普通以太网
- iSCSI HBA：用网卡硬件卸载 iSCSI 协议栈，减轻存储 I/O 对 CPU 的负担

### 如何判断网卡性能瓶颈？

- 用 `ethtool -S eth0` 查看硬件统计计数器：`rx_dropped`（接收环满丢包）、`tx_timeout`（发送超时）
- 高 `rx_missed_errors` → 接收缓冲区太小，需增大 ring buffer（`ethtool -G eth0 rx 4096`）
- 中断集中在个别 CPU 核心上 → 调整 IRQ 亲和性或将 RSS 队列数设为 CPU 数
- 大量小包 → 检查 PPS 是否触碰网卡上限

### 网卡在现代架构中的位置

对于云原生和虚拟化环境，网卡的角色进一步升级：
- **SR-IOV**：将一块物理网卡虚拟为多个独立 VF（虚拟功能），直通给虚拟机，绕过 Hypervisor 软件交换，性能接近裸金属
- **DPDK**：绕过内核网络栈，直接在用户态操作网卡，实现极高的 PPS（100 Gbps 线速小包）
- **SmartNIC**：在网卡上集成了 CPU/FPGA，可以完成加解密、防火墙、负载均衡等数据处理，进一步减轻主机 CPU 负担
