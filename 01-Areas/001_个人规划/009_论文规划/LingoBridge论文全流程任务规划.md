**定位**：这是在一切开始前的"接管战场"阶段。不跳过——没有这份审计，后续所有时间估算都是空中楼阁。

### Phase 1：数据工程与基线复现

**定位**：建立"可比的测量尺度"。如果没有这一步，你做出来的任何提升都可能是评价协议差异而非真正的方法优势。

#### 1.1 核心任务

| 任务编号  | 任务                    | 输入                                    | 输出                        | 预估工时 |
| :---- | --------------------- | ------------------------------------- | ------------------------- | :--: |
| P1-T1 | **内部数据清洗与 Schema 冻结** | 统一交互日志                                | 清洗后的数据集 + 冻结 schema 文档    | 5 天  |
| P1-T2 | **外部数据集准备**           | FoundationalASSIST / SpeechOcean762 等 | 标准化格式的外部数据集（与内部统一 schema） | 5 天  |
| P1-T3 | **DKT 基线复现**          | pyKT                                  | 可运行 DKT 脚本 + 复现指标记录       | 3 天  |
| P1-T4 | **simpleKT 基线复现**     | pyKT                                  | 可运行 simpleKT 脚本 + 复现指标记录  | 4 天  |
| P1-T5 | **sparseKT 基线复现**     | pyKT                                  | 可运行 sparseKT 脚本 + 复现指标记录  | 4 天  |
| P1-T6 | **基线对比矩阵**            | P1-T3/4/5 的结果                         | 所有基线在统一协议下的指标汇总表          | 2 天  |

**交付物清单**：
- `dataset_card.md` — 数据集说明书（字段定义、统计分布、拆分策略）
- `baseline_results.csv` — 所有基线的完整指标
- `baseline_reproduction_log.md` — 复现过程记录（环境、参数、种子）

**关键路径节点**：P1-T6 完成 = Phase 2 可以开始。P1-T1 和 P1-T2 可以并行。

#### 1.2 内部数据 Schema（冻结后）


| 字段                 | 类型     | 说明           | 是否必须 |
| ------------------ | ------ | ------------ | :--: |
| `user_id`          | string | 去敏后的用户标识     |  ✅   |
| `item_id`          | string | 题目唯一标识       |  ✅   |
| `concept_id`       | string | 关联知识点        |  ✅   |
| `timestamp`        | int64  | Unix 时间戳     |  ✅   |
| `prompt_text`      | string | 题面原文         |  ✅   |
| `reference_answer` | string | 参考答案         |  ✅   |
| `learner_answer`   | string | 学生实际回答       |  ✅   |
| `correctness`      | int    | 0/1 标签       |  ✅   |
| `latency_ms`       | int    | 作答耗时（毫秒）     |  推荐  |
| `hint_used`        | int    | 使用了多少次提示     |  推荐  |
| `attempt_index`    | int    | 同一题第几次尝试     |  推荐  |
| `audio_uri`        | string | 录音路径（如有语音功能） |  可选  |
| `asr_text`         | string | ASR 识别结果     |  可选  |
| `phoneme_seq`      | string | 音素序列         |  可选  |

### Phase 2：核心方法实现 — Edit-aware Knowledge Tracing

**定位**：论文的心脏。三个月的短路线论文能不能立住，全看这一阶段。

#### 2.1 核心任务

| 任务编号  | 任务                           | 输入                                     | 输出                                                        | 预估工时 |
| :---- | ---------------------------- | -------------------------------------- | --------------------------------------------------------- | :--: |
| P2-T1 | **字符级编辑距离特征工程**              | 清洗后的 learner_answer + reference_answer | Levenshtein 距离、Damerau-Levenshtein 距离、长度归一化残差             | 3 天  |
| P2-T2 | **编辑操作分布特征工程**               | P2-T1 的输出                              | insertion/deletion/substitution/transposition 占比向量、错误位置分布 | 3 天  |
| P2-T3 | **Token 级编辑特征**              | learner_answer + reference_answer      | 词级编辑距离、词级操作分布                                             | 2 天  |
| P2-T4 | **特征融合模块设计**                 | P2-T1/2/3 特征 + simpleKT/sparseKT 源码    | 在交互 embedding 中追加 edit 特征的代码实现                            | 5 天  |
| P2-T5 | **Edit-aware simpleKT 完整实现** | P2-T4 + simpleKT 基线                    | 端到端可训练的 Edit-aware simpleKT                               | 5 天  |
| P2-T6 | **Edit-aware sparseKT 完整实现** | P2-T4 + sparseKT 基线                    | 端到端可训练的 Edit-aware sparseKT                               | 4 天  |

**交付物清单**：
- `edit_features.py` — 编辑特征提取模块（含单元测试）
- `edit_aware_simplekt/` — 完整实验包
- `edit_aware_sparsekt/` — 完整实验包

**关键路径节点**：P2-T5 完成 = Phase 3 主实验可以启动。P2-T6 是变体对照，可延后到 Phase 3 中期。

#### 2.2 编辑特征规格


| 特征组     | 特征名                    | 维度  | 说明                          |
| ------- | ---------------------- | :-: | --------------------------- |
| 单值指标    | `levenshtein_dist`     |  1  | 字符级标准化 Levenshtein 距离       |
| 单值指标    | `damerau_levenshtein`  |  1  | Damerau-Levenshtein 距离（含转置） |
| 单值指标    | `length_norm_residual` |  1  | (编辑距离 / 参考答案长度) 的标准化残差      |
| 操作分布    | `ins_ratio`            |  1  | 插入操作占比                      |
| 操作分布    | `del_ratio`            |  1  | 删除操作占比                      |
| 操作分布    | `sub_ratio`            |  1  | 替换操作占比                      |
| 操作分布    | `trans_ratio`          |  1  | 转置操作占比                      |
| 位置分布    | `error_head_ratio`     |  1  | 前半段的错误占比                    |
| 位置分布    | `error_tail_ratio`     |  1  | 后半段的错误占比                    |
| Token 级 | `token_levenshtein`    |  1  | 词级 Levenshtein 距离           |
| Token 级 | `token_edit_ops`       |  4  | 词级操作分布向量                    |

> 总计约 14 维 edit 特征，注入交互 embedding 时通过一个小 MLP 映射到与原始 embedding 相同的维度空间。

### Phase 3：实验设计与执行

**定位**：这是论文中审稿人盯得最紧的部分。实验设计必须有"不可抵赖性"——每个消融都有清晰的对立面，每一条结论都有数据支撑。

#### 3.1 主实验矩阵

| 任务                               | 数据集                                 | 模型变体                                                                  | 指标                        |
| -------------------------------- | ----------------------------------- | --------------------------------------------------------------------- | ------------------------- |
| Next-Response Prediction（KT 主任务） | LingoBridge 内部 / FoundationalASSIST | DKT / simpleKT / sparseKT / Edit-aware simpleKT / Edit-aware sparseKT | AUC, ACC, BCE, Brier, ECE |
| Error Diagnosis（错误诊断）            | LingoBridge 内部（仅有文本回答的题）            | simpleKT vs Edit-aware simpleKT                                       | CER, WER, 编辑操作分类 F1, MAE  |
| Cross-Dataset Generalization     | 内部 → 外部 互迁                          | 最强两个变体                                                                | AUC drop                  |

#### 3.2 核心任务

| 任务编号  | 任务                         | 输入                  | 输出                                       | 预估工时 |
| :---- | -------------------------- | ------------------- | ---------------------------------------- | :--: |
| P3-T1 | **主实验：KT 预测任务**            | P2-T5/6 模型 + P1 数据集 | 所有模型 × 所有数据集的完整指标表                       | 5 天  |
| P3-T2 | **主实验：Error Diagnosis 任务** | 最优模型变体              | 错误诊断指标表 + 误差案例分析                         | 4 天  |
| P3-T3 | **消融实验 — 特征消融**            | 完整模型                | 去掉 edit 特征 / 只保留标量 / 去掉操作分布 / 去掉 token 级 | 3 天  |
| P3-T4 | **消融实验 — Backbone 敏感性**    | 完整模型                | 把 simpleKT 换回 DKT / 把 sparseKT 换回 DKT    | 2 天  |
| P3-T5 | **跨数据集泛化实验**               | 内部+外部数据集            | 迁移结果表                                    | 3 天  |
| P3-T6 | **子群体公平性实验**               | 按平台/先验能力分层的数据       | subgroup AUC + calibration gap           | 2 天  |
| P3-T7 | **可视化与案例分析**               | P3-T1/2 的结果         | 热力图、错误剖面图、t-SNE 聚类图、典型案例详解               | 3 天  |

**交付物清单**：
- `experiment_results/` — 所有实验的原始日志、checkpoint、配置
- `figures/` — 论文级质量的图表（矢量格式）
- `case_studies.md` — 不少于 5 个典型案例的深度分析

#### 3.3 实验配置标准


| 配置项 | 规范 |
|------|------|
| 随机种子 | 固定 3 个（42, 123, 2024），报告均值 ± 标准差 |
| 数据拆分 | 按用户拆分（user-level split），80/10/10，避免 label leakage |
| 评估协议 | 严格遵循 pyKT 协议：固定窗口、固定预处理、固定指标 |
| 日志系统 | Weights & Biases 或 TensorBoard |
| 硬件记录 | GPU 型号、CUDA 版本、单次训练耗时 |

```
                               ┌──────────────────────────────────────────┐
                               │              关键路径（最长链）            │
                               │                                          │
P0-T1 → P0-T2 → P0-T4 → P1-T1 → P1-T3 → P1-T4 → P2-T1 → P2-T4 → P2-T5  │
 (3d)   (2d)   (4d)   (5d)   (3d)   (4d)   (3d)   (5d)   (5d)            │

 → P3-T1 → P3-T3 → P3-T7 → P4-T1 → P4-T2 → P4-T3 → P4-T4 → P4-T6 → P4-T7│

                                                                          │
  关键路径总时长：≈ 65 个工作日 ≈ 13 周                                    │
                                                                          │
                               └──────────────────────────────────────────┘

并行支线（非关键路径，可与主路径同时进行）：
├── P0-T5（pyKT 环境） ↕ P0-T4
├── P1-T2（外部数据）  ↕ P1-T1

```

> ⚙️ **关键路径解读**：从代码审计到论文投稿，不可并行的依赖链总长 13 周（65 个工作日）。这意味着即使你全力冲刺、没有任何外部延误，**最快也需要 13 周**。加上缓冲和修改，22 周是一个现实的目标。如果中途有重大返工（比如基线复现失败、edit 特征不 work），需要从缓冲中借用时间。
