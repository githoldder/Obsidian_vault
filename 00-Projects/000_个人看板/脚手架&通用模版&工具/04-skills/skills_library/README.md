## 命名规则

1. 文件名格式：`两位编号_能力名称Skill.md`。
2. 目录名格式：`两位编号_能力类别`。
3. 成体系的技能包可以保留子目录。
4. 实验性、低频、未验证 skill 不进入常驻根目录。
5. 高质量高频 skill 才保留；否则归档、合并或废弃。

---

## 达尔文原则

Skill 管理遵循“用进废退”：

1. 高频使用的 skill 保留常驻位。
2. 重复内容合并。
3. 低质量 prompt 归档。
4. 能沉淀成脚本的，不长期保留为口头提示。
5. 每个 skill 都要说明触发场景、输入、输出、执行步骤和验收标准。

**项目文档包**对应项目生命周期，细分三层结构：
AI产品经理应该是第一层
软件工程文档应该是第二层
项目管理文档应该是第三层
**技术信息包**
技术知识文档
**复盘成果展示包**
演示ppt（研究一下[reveal.js](https://revealjs.com/)）、checklist、演示脚本（演讲稿）、用户指南
